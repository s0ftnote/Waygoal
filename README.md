# Waygoal

**From a rough idea to something real.**

Waygoal 是一个基于 Pi 的本地无限画布会话空间。它让你跨越多个问题、分支和 Agent 会话，仍能看清讨论的来路、已经认可的判断，以及下一步可以做什么。

**右边连续聊，左边随讨论生长。** 你可以像普通聊天一样一直说下去；需要探索另一种可能时，从具体消息分叉，再把有用的发现带回。适用于创意、科研、写作、需求讨论和工程工作。

[简明使用指南](docs/usage.md) · [开发指南](docs/development.md) · [产品设计](docs/design/canvas-navigation-and-states.md)

## 怎样组织工作

一个工作目录可以有多张画布，一张画布可以容纳多个会话。已有会话先放在「未归类会话」，再由你加入相应画布。

- **会话**可以在同一张画布中展开、收起，并排查看多个讨论。
- **轮次卡片**对应真实的提问和回答，可以定位回原始消息。
- **同源分支**共用已核实的历史，从实际分叉点接出；原会话不在当前画布时，也能核对同源会话保留的历史。
- **右侧聊天**保留当前路径的完整历史，较早消息按需加载；画布导航与聊天输入相互配合。

例如，讨论一个活动方案时：

```text
活动目标 → 时间与预算
                 ├─ 探索观影方案 ── 找到适合的场地
                 └─ 探索桌游方案 ── 确认人数限制

选取两边的发现，作为材料带回下一轮讨论。
```

分支各自继续，跨分支的信息由你明确引用。一张卡片不等于一个新会话，继续聊天也不需要逐张点击卡片。

## 快速开始

开发环境使用 **Node.js 24**。在仓库根目录运行：

```sh
npm run setup
npm run dev
```

打开 [Waygoal](http://127.0.0.1:30142/waygoal)。当前版本复用 pi-web 宿主和 Pi extension；使用本机 Pi 的登录、模型、工具及已安装 skills。首次配置模型可参考[宿主说明](apps/web/README.zh-CN.md)。目前没有独立可安装的 Waygoal extension 包。

1. 点击左上角「工作目录 / 画布」入口，选择工作目录并新建画布。
2. 在空画布的输入框写下第一句。发送后，会话和第一张轮次卡片才出现。
3. 在右侧继续聊；需要探索另一方向时，在消息或轮次卡片上选择「从这里分叉」。

也可以使用「加入已有会话」接着已有讨论。它会把会话移入当前画布，保留原有历史；每段会话归属一张画布。

默认恢复上次打开的工作目录和画布。使用顶部入口可切换目录，也可在 URL 中通过 `?cwd=` 指定经过 URL 编码的绝对路径。普通目录即可开始，无需 Git 仓库、GitHub 账号、Matt skills 或票据。

## 主要操作

| 想做什么 | 怎么做 |
| --- | --- |
| 持续讨论 | 在右侧发送消息，左侧自动增加轮次卡片 |
| 切换会话、对照原文 | 点击会话或轮次卡片，右侧直接打开对应聊天并定位；各会话草稿分别保留 |
| 探索另一方向 | 从消息或卡片「从这里分叉」，在新会话里继续 |
| 选择会话内另一条路径 | 在画布的「画布工具 → 选择继续路径」中选择，或在旧分支历史中点击「切换到这条分支」 |
| 带回另一分支的发现 | 使用「引用回答」或「引用连线」，审阅材料后随下一轮发送 |
| 记住这轮的收获 | 打开卡片「所得」，自己填写或「请 Pi 提炼」，再确认保存 |
| 看清整体 | 使用「查看全部」或滚轮；展开「画布导航」后，点击或拖动缩略图移动视野 |
| 回到手头讨论 | 点击「定位对话」 |
| 收起顶部导航 | 点击左上角 Waygoal Logo；再次点击展开 |
| 调整聊天区域 | 在桌面布局拖动聊天框左侧、顶部或角上的调节柄 |
| 整理多个讨论 | 在「查看会话与票据」中查找，⌘/Ctrl 点选卡片后分组、整理位置或关联 |

**分叉、引用和关联是三件不同的事：**

- **分叉**：建立有真实来源的新会话。在聊天消息上分叉，包含所选消息；在轮次卡片上分叉，包含该轮结束前的历史，不带入其后的讨论。
- **引用**：把选定内容作为下一轮材料。发送前可查看范围、原文和来源，不会把两个会话的历史合并。
- **关联**：只在画布上标出联系，不向模型添加上下文。

单纯回看和定位不会发送消息或切换当前继续路径。只有明确选择路径、分叉或发送等操作，才改变讨论的继续位置。具体步骤见[使用指南](docs/usage.md)。

## 可选：把讨论关联到实际工作

有正式工作记录时，画布也可以展示地图、票据、依赖和关联讨论。一张票据可以关联多段会话，尚无讨论时可以从票据开始聊。票据状态来自来源记录；聊天结束或依赖满足都不代表工作自动完成。

- **本地来源**：读取工作目录下 `.scratch/<地图>/map.md` 与 `issues/NN-*.md` 的约定布局。
- **远程来源**：接收 Agent 交付的原文结果；GitHub 来源信息放在票据详情，真实 Map Ticket 通过父子线组织子票据，依赖另用虚线显示。交付后或点击详情中的“刷新父子与依赖关系”时，通过本机 `gh` 只读取得关系，不持续联网同步。
- **Map 容器**：框内是所属票据与关联讨论；点击标题查看 Map，拖动标题栏整体移动，点击箭头收起为摘要或展开。依赖箭头从前置票据指向后续票据。
- **整理票据**：在“画布工具 → 整理会话与票据”中点击“整理票据”，按真实归属排布并避开已展开的会话，可撤销上次整理。
- **Matt skills**：沿用已安装技能的方法和流程，由用户调用。输入 `/skill:名称` 使用已安装 skill，缺失时会提示。

普通聊天可以一直留在会话中，票据和 skills 都是按需使用的工具。

## 数据与当前边界

| 内容 | 由谁保存 |
| --- | --- |
| 会话消息、标题和真实路径 | Pi |
| 正式地图、票据、结论和依赖 | 本地文件或用户配置的 Tracker |
| 布局、分组、关联、引用快照和「所得」 | Waygoal 本地画布记录 |

画布记录位于 Pi 数据目录的 `waygoal/workspaces/` 下，按工作目录和画布隔离。聊天面板尺寸记在当前浏览器。刷新或重启后可以恢复工作现场。

「所得」是画布上的标注，模型提炼的文字需要你确认；它不会自动改写聊天原文或进入下一轮输入。共享历史只依据真实来源和消息校验，不按相似标题拼接；来源不完整时会明确说明。

仓库仍处于 alpha 阶段。本文描述当前代码；本次源码预发布说明见 [v0.1.0-alpha.4](docs/releases/v0.1.0-alpha.4.md)，历史研究与原型记录位于 `docs/research/`。

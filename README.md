# Waygoal

**From a rough idea to something real.**

Waygoal 是通过 Pi extension 接入的本地无限画布会话空间。用户可以从一段讨论分出去探索，看见来源与当前路径，再回看或继续原来的思路。它帮助用户理清想法、保持方向，并通过行动与反馈逐步形成自己认可的实际结果；面向工程、创意、内容和活动。

普通 Pi 会话就能成为画布上的起点，无需 Matt skills、票据、Git 仓库或 GitHub 账号。使用 Matt skills 并实际产生地图和票据后，画布呈现这些工作记录及其关系，相关会话可以挂在票据上。产品保留 skills 原有的方法与流程，提供导航、状态展示和少量提示；技能选择由用户发起。

## 会话空间与票据的关系

以下是目标设计，当前原型的接入范围见下文。

```text
工作区（一个工作目录）
├─ 画布 A
│  ├─ 独立会话：海报灵感
│  │  └─ 从某条消息分出的真实讨论分支
│  ├─ 独立会话：音乐选择
│  └─ Wayfinder 地图：想清楚周末聚会方案
│     ├─ #12 确定活动形式
│     │  └─ 关联会话
│     │     ├─ 观影方向的讨论分支
│     │     └─ 桌游方向的讨论分支
│     └─ #13 确认场地条件
│        └─ 尚无会话 → 开始讨论
└─ 画布 B
   └─ 其他想法和会话
```

图中缩进表示组织与关联，票据之间的依赖另行展示。工作区可以有多张画布，一张画布可以有多个互不相连的起点；用户可以拖动摆放、命名分组和手动连线。

**票据在上、会话在下：从要解决的事情进入相关讨论。** 有票据时，会话及其分支在票据下展开；无票据的会话独立留在画布。票据与会话各自显示身份和状态：

| | 会话 | 票据 |
| --- | --- | --- |
| 标题 | Pi 会话名称，可手动修改或请求生成 | Tracker 中的票据标题与编号 |
| 状态 | Agent 运行、等待输入等会话状态 | 来源记录的待解决、阻塞、已解决或取消等工作状态 |
| 打开后 | 聊天记录与真实分支 | 票据原文、依赖及关联讨论入口 |

一张票据可以关联多条讨论分支。默认保留一张票据卡，展开查看其讨论；创建票据不要求立即创建会话，分叉也不复制票据。关闭聊天不等于解决票据，所有已知阻塞前提满足后，下游变为可推进，不自动完成或启动下一段聊天。当前正在查看哪个节点，是独立的导航标记。

画布中的连线保留三种不同含义：

- **真实分叉来源**：实际从哪段讨论、哪个位置分出。
- **票据依赖**：Tracker 记录的完成前提，可以有多个前提和汇合。
- **手动关联**：用户为整理而建立的联系，不改变聊天上下文或票据依赖。

调用 Matt skill 本身不保证产生票据，例如一次普通澄清可以始终留在会话中。有真实票据及明确关联时才展示挂载关系，不根据相似标题或聊天内容猜测。

## 内容由谁保存

| 来源 | 保存内容 |
| --- | --- |
| Pi | 会话历史、标题和真实对话路径 |
| 用户配置的 Tracker | 正式地图、票据、结论和依赖；可以是本地文件或外部平台 |
| Waygoal 本地画布记录 | 布局、分组、手动关联、票据与会话的关联，以及来源原文快照 |

目标接入方式是：Agent 成功操作来源票据后，把来源身份和原文文件或工具结果引用交给 Waygoal；程序读取原文用于展示，Agent 无需抄写第二份正文。快照保留来源与取得时间，外部修改需后续核对。具体约定见 [票据来源与持久化](docs/adr/0001-tracker-authority-and-local-canvas-records.md)。

对象定义见 [CONTEXT.md](CONTEXT.md)，关系边界见 [会话与票据地图](docs/adr/0003-discussion-and-ticket-map.md)，交互方案与待验证项见 [画布导航与状态](docs/design/canvas-navigation-and-states.md)。

## 当前原型

已确认的产品规格见 [Spec #1](https://github.com/s0ftnote/Waygoal/issues/1)，实现拆分、阻塞关系及建议顺序见[实现票清单](.scratch/waygoal-tickets/README.md)。

当前是 Pi × Wayfinder 的接入原型：把本地工作目录中的 Markdown 地图和票据变成可浏览的画布，点击节点开始或继续关联的 Pi 对话。上述普通会话画布、手动整理、多分支展开及通用来源通知尚未完整接入；现有固定 Wayfinder 入口不代表最终产品入口。产品工作指引见 [AGENTS.md](AGENTS.md)。

## 启动

```sh
npm --prefix prototypes/pi-web ci --ignore-scripts
npm run dev
```

打开 http://127.0.0.1:30142/beacon 。使用本机已有 Pi 登录与 skills，新节点使用 `openai-codex/gpt-5.6-luna`，不改变 Pi 的全局默认模型。已有的 pi-web 30141 不受影响。

原型的 `/beacon` 路由、界面名称及内部标识暂时保留，文档中的产品名称统一为 Waygoal。

第一次试用默认打开 `playground/`：这是虚构的朋友放映会示例。点击「希望朋友带走什么感受？」继续 Luna 已经提出的问题，研究节点可以直接读结果。其余节点等待前面的答案。

也可以在顶部切换到任意已有工作目录。没有地图时，先写想法并开始澄清目的地；Agent 创建地图后会出现在画布中。无需 Git 仓库或导入流程。

## 本次实现的范围

- 当前读取 `.scratch/<effort>/map.md` 和 `issues/NN-*.md`；GitHub tracker 的画布适配尚未实现。
- 目的地、问题类型、问题/结论摘要、状态、依赖关系以及未知方向可见。
- 拖动画布、缩放、拖动节点；节点位置保存在浏览器中。
- 首次点击节点创建真实 Pi 会话并调用 Wayfinder；后续点击恢复同一会话。依赖未满足的节点可阅读，不创建新会话。
- 票据是状态来源。`.beacon-prototype/sessions.json` 只保存节点与 Pi 会话的关联；Pi 自己保存聊天记录。
- 小型 Pi extension 在实际地图变化时发送事件；浏览器也每 2.5 秒刷新，以接收其他会话或外部编辑。
- 这个实验进程启用 pi-web 的内置研究子代理；没有更改全局子代理设置。

这是验证接入方式的可运行原型。页面重载后需再次点击节点恢复对话；GitHub、票据重命名后的关联迁移、多进程争抢、自动布局优化尚未处理。节点默认布局根据阻塞关系分层，虚线连接没有前置依赖的票据与目的地，实线表示依赖；它不是 Pi 内部聊天分支树。

## What to build

验证 Agent 按正常 skill 流程成功取得远程票据后，来源身份和原始结果怎样可靠到达 Web，再接入已有快照与画布。交付一个真实 GitHub 只读路径及一个离线自定义 tracker 样本；Web 无需另登录平台。

## Acceptance criteria

- [ ] 先以真实 skill 调用及宿主操作验证最小接入机制，记录成功来源操作、结果引用与画布更新的端到端证据。沿用已有通知实验，核实注册工具或明确受支持的宿主捕获方式是否能稳定触发；不预设任意 Bash／gh 输出均可自动提取，也不靠修改 Matt 流程或增加长系统提示来强迫通知。若只能部分捕获，明确支持范围和未同步状态。
- [ ] 接入只交付来源身份与可读取的原始结果引用，由程序取得内容；明确支持的格式提取正文、已取得的评论、状态和关系，不让 Agent 在通知中重写正文或把模型改写当原文。来源操作成功与画布同步成功分别记录。
- [ ] GitHub 与离线自定义样本复用本地票据的快照和画布身份机制；相同裸编号跨来源不冲突，不另建平台会话模型。自定义样本仅验证边界，不增加新的实际平台集成。
- [ ] 成功提交的正文文件仅在能代表最终内容时复用；来源平台改写后读取最终记录。原始引用须在失效前取得，未取得显示未同步，并能在重新取得来源后重试；失败或重复交付不新增重复节点，旧／顺序不明的结果不静默覆盖已确认的新状态。
- [ ] 显示实际取得的正文、评论／答案及附件引用边界、时间和待核对状态；外部变化通过后续读取更新，未知格式明确未支持，不承诺全平台实时同步。Web 不维护第二份正式正文，不要求新的 OAuth 配置。
- [ ] 用真实 GitHub 只读结果核对格式和接入链路，使用保留的原始结果做离线回归，覆盖自定义样本、重复／旧结果、失效引用后重试、缺失评论和宿主重启；不向真实外部票据写入测试内容。

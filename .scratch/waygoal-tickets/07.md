## What to build

把已认可的 B 交互接上真实 Pi：空票开始讨论，已有会话挂在票下或收进票里，分支仍属于原票。

## Acceptance criteria

- [ ] 采用 B 基线：票据平铺，票下展示会话及来源分支，不套 A 的大容器。未挂票的会话继续独立存在。
- [ ] 复用已有不发送提示的新建会话能力和草稿保存能力；空票的开始入口按需建立真实关联会话，仅准备精简 Wayfinder 调用和实际来源引用。草稿可改，发送前不写入用户消息、不执行 skill；沿用用户模型及 tracker 配置，不强制模型或固定长提示。
- [ ] 同一次开始的并发／重复请求复用会话，恢复票据不重发命令；用户明确另开讨论时可建立另一段会话。
- [ ] 一票多会话或分支，fork 保留票据关联，不复制票据或新增阻塞边。明确记录票下上次继续位置，可恢复或选择另一段讨论。
- [ ] 挂出和收起共用同一会话。收起后可从票内继续，不强制重新展开；回看、关闭面板和收起不停止 Agent，不改变票据工作状态。
- [ ] 阻塞票和已解决票仍可查看和补充讨论，不以聊天开始解除阻塞；失效会话关联明确显示，不静默替换。
- [ ] 用持久画布记录保存票据关联和展开／继续位置，替换旧的一票单绑定限制；重启后恢复。从实际页面验收空票、明确发送、双分支、回看、收起后继续和重复点击，并用 gpt-5.6-luna 做有界真实试跑。
- [ ] 在票据讨论入口提供可关闭和重开的简短操作／方法提示，建议标注出处，按明确入口或用户操作呈现，不分析聊天、不调用模型、不注入聊天上下文；关闭后核心路径仍可用。
- [ ] 用一个聚会策划样例走查票据下的开始、分叉、深入和返回，保留实际界面截图及状态证据，邀请用户确认是否能认清位置和继续方向；记录尚未确认的体验，不以测试通过或模型试跑替代用户判断。

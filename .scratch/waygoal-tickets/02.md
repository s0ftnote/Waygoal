## What to build

从一条消息探索不同方向，在画布上看见来源，回看原路径或兄弟路径，再明确选择继续位置。

## Acceptance criteria

- [ ] 在可分叉消息处显示入口并调用真实 Pi 操作，展示来源会话及消息位置，保留原路径；用户能辨认原路径、新路径与当前所在位置，不把每轮问答自动变成节点。
- [ ] 区分新会话 fork 与现有会话内的分支：读取和展示实际 Pi tree，内部路径不伪造独立会话文件。保留对应操作对选中消息和草稿的原生语义。
- [ ] 复用已有只读历史读取能力，并在界面上分开当前查看位置与实际继续位置。查看来源或兄弟历史不调用改变活动叶子的导航，不新增消息；明确继续才切换活动路径，下一次发送进入所选路径。
- [ ] 身份同时考虑会话与条目范围，兄弟分支内容不自动并入当前上下文；运行中限制沿用 Pi，不能静默打断任务。
- [ ] 刷新和宿主重启保留来源及最近位置；缺失记录明确提示，不按相似标题绑定到另一段历史。分叉和返回的过渡帮助定位，减少动态效果时仍可理解。
- [ ] 用真实 Pi 存储和 SDK、可控模型输出验证双分支往返，并检查实际消息与活动叶子；追加一次 gpt-5.6-luna 有界真实运行，保留证据，不以模型回答代替状态断言。
- [ ] 通过实际分叉、深入、返回原讨论的操作走查，并保留截图，检查来源、两条路径及当前继续位置是否可辨认。会话内分支需在整体导航中可发现，不以只放入聊天面板作为硬性限制；自动测试通过不等于已完成体验确认。

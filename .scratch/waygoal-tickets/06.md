## What to build

先把明确支持的本地 Markdown 地图和票据读入画布：复用已有文件扫描与变更检查，直接从来源文件取得标题、正文和状态，供用户预览及回看；不要求 Agent 再抄写或专门通知一次。远程来源接入在后续票中验证。

## Acceptance criteria

- [ ] 明确首版支持的本地 Markdown 布局与字段，复用已有地图／票据扫描器；启动、用户刷新及已有 extension 变更检查能发现创建和修改。扫描范围跟随工作目录；未配置或不支持的布局明确说明，不把现有固定格式宣称为任意本地 tracker 都适用。
- [ ] 程序直接读取来源文件形成快照，不要求 Agent 维护第二份正文、不强加一次发布工具调用，也不改造 Matt skill 流程。复用共同的来源记录边界，远程工具结果的触发与通知机制留给远程接入票验证。
- [ ] 真实来源地图与票据可展示标题、类型、状态和忠实预览，票据可先无会话。查看不启动 Pi 会话；已取得依赖与未知关系可辨认，复用现有阻塞判断，本票不宣称完成后续全部状态变化与动效。
- [ ] 完整视图保留原始结构、答案及取得范围，显示来源与读取时间；已取得的原文和来源入口可回看，缺失内容不冒充完整。
- [ ] 来源身份包含工作范围与来源文件身份，跨地图同号不混淆；改标题、重复扫描不新增节点。布局和快照持久保存，宿主重启后仍可查看。文件移动或删除不按相似标题猜测绑定。
- [ ] 无法读取、来源缺失或读取失败时，已保存快照明确显示过时／不可核对，不创建虚假成功记录或把未知状态改成已解决；连续修改后显示最后成功核对的来源内容。
- [ ] 通过真实支持格式的本地文件创建、读取、修改、重复刷新与重启检查画布结果，覆盖同号、缺失依赖、改标题及读取失败；不先搭建通用事件总线、tracker 插件体系或全格式自动识别。

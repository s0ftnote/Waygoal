# 画布导航、轻量提示与状态变化

已确认的展示方向；本文件不代表主原型已完成实现。服务于“保持方向”，沿用 Pi 聊天。轮次卡片呈现原有对话，不由模型另行拆解为问题卡。

## 2026-09-20：点击卡片直接打开聊天

本节替代早期“点其他会话先在画布内预览”的默认行为，改善跨会话切换时的方向感。

- 点击会话卡片，右侧直接打开它；点击其当前路径上的轮次，同时定位原文。打开会话不改动 Pi 的历史叶节点，不把会话倒退到所点轮次。
- 各会话草稿及待发送材料分别保留。回到同一会话的普通轮次，只滚动历史，不重建输入框。
- 点击不在当前路径上的轮次，在同一个右侧面板阅读历史；此时隐藏但保留原输入框。提供“返回当前聊天”和“切换到这条分支”，避免看着旧分支却误发到当前路径。
- 只有明确切换分支或分叉才修改 Pi 的继续位置；运行中的会话可以查看，不能切换路径。
- 查看引用来源仍不改动当前聊天身份与草稿，阅读也使用右侧面板，不额外弹出画布浮窗。

验收：跨会话点轮次可直接切换并定位，来回切换保留草稿且两边叶节点不变；旧分支阅读时输入框不可操作，返回后恢复同一个输入框；明确切换分支后显示对应历史。

## 2026-09-15 交互基线：持续聊天，画布生长

用户体验后确认此版，作为后续真实接入的交互基线，依据见 [ADR 0006](../adr/0006-continuous-chat-and-turn-cards.md)。以下是已确认方向。真实 Pi 宿主接入及其验证范围见[接入记录](../research/turn-cards-integration-results.md)；后文历史记录仍按各自日期理解。

- **连续聊天：** 右侧沿用 pi-web 的完整当前路径历史、输入框、运行状态和快捷节点导航。正常连续发送时，左侧新增或更新轮次卡片，右侧不因卡片生长、选中变化或画布移动而重建，不要求逐张选卡片接着聊。
- **卡片减量：** 默认显示编号、问题和回答预览；不显示“可回看”“一轮问答”等重复标签。具体消息操作在对话中按需出现，卡片不常驻另一套展开、分叉按钮；连线点在连线操作时呈现。
- **双向定位：** 点击当前路径上的卡片，只定位右侧原文；右侧快捷节点导航及消息定位入口同步定位左侧卡片。查看不改变活动路径，保留未发送输入；历史始终可以上下回看。
- **其他路径：** 点击其他分支先在画布内预览，右侧持续对话不被替换。明确选择 Tree 路径或分叉后，才改变继续路线，右侧显示该路径的完整历史。不同路径的未发送输入分别保留；预览的位置、尺寸和动效可继续打磨。
- **引用后仍连续聊：** 用户可以手动把已有卡片连到下一轮，查看并调整所选材料，再从同一个右侧输入框发送。引用保留来源，不改旧轮次已使用的材料；“仅作关联”仍只负责整理，不加入下一轮输入。普通聊天无需连线。

验收：连续发送三轮时，已有历史、输入框和输入焦点保留，左侧生长三张卡片；有未发送输入时定位旧轮次或预览另一分支，当前路径和输入不变；明确分叉后可持续发送，再通过 Tree 返回原路径。引用另一分支材料后，仍可在当前路径连续聊天。

原型保存在独立分支 [`codex/prototype-turn-cards-20260915`](https://github.com/s0ftnote/Waygoal/tree/codex/prototype-turn-cards-20260915/apps/web/experiments/turn-cards-prototype)，交互版本提交为 `cf8b7f6`；用户随后以“ok 就这样吧”确认。浏览器已验证连续发送、节点身份保留、双向定位、输入恢复、明确切换与引用；模型回复和消息树均为内存样例。这些检查不代表真实 Pi 接入、上下文编译或持久化已完成。

## 2026-09-15 跨会话画布基线

用户体验跨会话原型后以“ok 的”确认，作为真实接入的交互依据，延续上面的连续聊天基线。

- **共同画布：** 不同会话的轮次可以同时展开、自由摆放。分叉深入时原路径仍留在原位，查看其他会话不将画布过滤为单个会话。
- **关系可追溯：** 连续历史、分叉来源、材料引用和手动关联分别呈现。待发送材料连到当前聊天的下一轮；发送后，引用线落到实际使用材料的轮次。点选引用可以回看当时使用的原文和来源，后续改选不改写旧轮次。
- **查看与继续分开：** 点击其他会话的卡片或关系先在画布内预览，保持右侧活动会话、历史和草稿。用户明确选择继续会话、Tree 路径或分叉时才切换；各会话、各路径的文字与待发送引用分别保留。卡片和右侧快捷节点仍双向定位。

验收场景：主线留下草稿，从同一个问题分别探索 A、B；回主线审阅并引用两条探索的材料，从同一个输入框连续发送；沿引用找到来源时，当前聊天和未发送输入保持不变。普通关联和取消关联不影响发送材料。卡片仍只保留编号、问题和回答预览，不为这些关系增加常驻状态标签。

原型保存在本地独立分支 `codex/prototype-cross-session-canvas-20260915`，交互提交为 `98c6e02`，路径为 `apps/web/experiments/cross-session-prototype/index.html`。README 记录演练与浏览器核对范围。原型使用内存样例与模拟回复，此次确认不代表真实 Pi 来源处理、持久化或体验验收已经完成。

真实接入现已支持共同画布、关系预览、引用原文回看及布局持久化，验证范围见[接入记录](../research/turn-cards-integration-results.md#跨会话共同画布接入)。原型共用分叉前历史卡片来展示共同来路；实际代码按会话 ID、entry ID、明确的分叉来源及完整可见条目摘要核对，不能仅因不同文件中的 entry ID 相同就合并来源。Pi 历史保持单父节点，引用关系保存在其上层。具体视觉参数、收起方式和大规模图的展示继续通过真实使用调整。

## 2026-09-16：B 布局与空画布入口（用户已确认）

- 画布铺开，右侧对话浮在其上；左上收起工作目录与画布管理，左下保留回到当前轮次、看全局和更多操作。
- 分叉、引用等操作跟随选中的卡片；点击空白、Escape 或卡片离开可视区域时收起，不常驻顶部。
- 没有会话的新画布从居中的输入框开始；打开页面不创建 Pi 会话。首次发送保存为真实轮次后，输入框移到右侧、画布显现并呈现第一个节点。同一个聊天组件保持连续；发送失败留在入口，减少动态效果时直接切换布局。
- 画布是 Pi 会话列表上层的归类，一段 session 归属一个 canvas ID；按画布筛选会话。尚未归类的历史会话归入默认主画布，新建画布不自动收进历史会话。
- 工作区菜单提供“导入已有会话”：显示来源画布，将原会话移入当前画布，保留 Pi 身份和完整历史。导入不复制会话、不发送提示、不改变 Pi 当前路径。可在原画布通过同一入口移回。

B 的参考原型位于独立分支 `codex/prototype-ux-clarity-20260916`。实现与验证记录另见接入记录；小规模原型的确认不等于大规模画布已验收。

## 设计重心

交互、视觉与动效是产品的主要投入方向。画布承载 Pi 会话及可选票据，方法沿用原始 skills；不通过另加流程干预创造差异。

优先打磨三个实际动作：从讨论中分出一条新路径、打开节点后回到整体、辨认工作记录发生的变化。动效连接操作前后的位置与关系，使用户看懂“从哪里来、到了哪里、什么变了”。分叉生长、展开收起、镜头移动与缓慢点亮是可试验的表现形式，不是已经定稿的动画方案。

交互优先于动画完整播放：用户可继续操作，阅读焦点保持稳定，减少动态效果时仍能通过位置、连线和文字理解相同信息。动画展示已发生的操作或已取得的来源状态，不制造进度、不触发工作流。用真实分叉与返回样例验证方向感，再调整具体布局、节奏和视觉细节。

## 导航与说明

### 工作区与多画布（已确认）

用户可以在当前工作区新开画布，也可以切换工作区。工作区以工作目录为基础，一张画布可以有多个互不相连的讨论起点；不要求所有讨论共享一个总目标。新开画布与切换工作目录是不同操作，新画布不隐含建票或调用 skill。

切换目录支持浏览文件夹、直接输入路径和最近打开的目录。浏览从当前工作目录开始，可进入子目录或返回上级；明确选择当前文件夹后才切换画布，浏览和取消不改变当前工作区，不创建会话或发送消息。

体验验证：用户在同一工作区分别建立“产品”和“活动”画布，能够切换并恢复各自的节点布局和位置；切换到另一工作区时，清楚知道当前使用的工作目录。入口布局通过原型验证。

### 独立会话、标题与手动整理（已确认）

没有关联的会话是正常的独立节点。用户不必使用 Matt skills、创建票据或整理连线才能聊天；会话管理的主要入口是画布，不另设传统会话列表作为主界面。

- **标题识别：** 会话节点直接展示 Pi 保存的会话标题，支持用户请求生成标题或手动改名，供扫视与搜索定位。用户手动命名后，不因继续聊天或刷新而自行覆盖；再次生成仍由用户发起。没有名称时用首条消息的简短片段等已有内容作显示回退，不把回退文本当成已保存标题。
- **自由摆放：** 用户可拖动节点，位置稳定保留；新会话出现在容易发现的位置。星系是视觉意象，不使用随机散点和持续漂移承担管理工作。
- **初始排列与局部整理：** 新发现的独立会话填入逐渐扩展的紧凑网格；有明确来源的新分叉优先放在来源右侧，遇到占位则寻找附近空位。已有坐标保持不变。用户可用 `⌘/Ctrl` 点选或“全选会话”，再点“整理所选”：选中的真实分叉和已有分组聚在同一区域，零散会话紧凑排列，避开未选卡片。只改位置，不创建分组、不分析内容、不修改关联。
- **撤销整理：** 当前画布保存最近一次整理前后的坐标，刷新后仍可撤销。只恢复这次整理涉及的卡片；后来新增的会话和其他画布不受影响。相关卡片被手动移动后，这次撤销失效，避免覆盖后来的摆放。第一版不提供多步撤销；分区不自动命名，已有旧布局要主动整理才变化。
- **分组：** 框选若干节点，圈成一组并起名；缩小时看组名，展开后看节点。整理只改变画布记录，不新建会话或改动聊天内容。
- **手动关联：** 用户按需连接节点，可附一句说明。它表达“我认为有关”，不修改真实分叉来源、合并上下文或创建 tracker 依赖；删除手动关联只取消该联系。
- **找回内容：** 提供标题搜索定位、最近访问和回到当前会话的快捷入口，避免靠记住坐标寻找会话；这些入口的具体形式通过原型验证。

关系的来源必须能辨认：真实分叉来自 Pi 操作，票据依赖来自 tracker，手动关联来自用户整理。分组名称由用户维护；票据节点取票据标题，关联会话仍保留自己的名称，不因会话改名修改原票据。具体线型和展开样式待验证。

体验样例：三个独立会话“活动海报”“场地预算”“开场音乐”被圈为“周末聚会”；用户把“活动海报”改名为“给老朋友的邀请”，已有位置、分组和连线保持不变，并能通过新标题找到它。将“开场音乐”与海报手动关联后，两个会话仍保留各自历史，票据依赖没有变化。

### 真实分叉（已确认要做）

直接服务于“保持方向”：用户能发现分叉入口，知道从哪条消息分出，并看清当前讨论路径。以下是首轮实现与体验验证的要求，具体排版尚未确定：

- 在可分叉的位置提供清楚的“从这里分叉”操作，产生后显示来源连接、原路径与新路径，并标明当前继续的位置。
- 区分“查看这段历史”与“在这里继续说”。查看只改变展示；明确选择 Tree 中的路径、发起分叉，或从指定路径发送，才改变实际继续路径。回到来源不自动合并分支结论，带结论返回另行发起。
- 轮次卡片随真实问答生长，连续消息可以收起；卡片保留具体消息的来源，不为展示而新建会话或票据。
- 普通 Pi 会话也具备这些能力。只有关联了真实票据，才显示由来源记录支持的依赖与完成状态。

最小体验样例：在同一问题处分别探索 A、B，用户能看见共同来源、识别当前路径、只查看另一条路径，再明确选择继续。整个过程不需要安装 Matt skills 或创建 tracker；查看动作不改变 Agent 的活动路径，也不自动发送消息。

### 票据在上、会话在下（已确认）

有票据的部分以票据作为进入讨论的上层入口，按 [ADR 0003](../adr/0003-discussion-and-ticket-map.md) 的层级呈现：

- **打开票据**：看问题、状态和票据下面的会话。
- **尚无会话**：提供“开始讨论”，用户点击后按需创建关联会话。Wayfinder 票据可准备对应调用和准确票据引用，由用户发送；查看或展开本身不发送消息。
- **已有会话**：提供继续讨论入口；有多个会话或分支时展开选择，不凭票据状态替用户选定路径。
- **收起票据**：收起下层讨论，票据仍留在画布，保留讨论数量和可识别的展开入口；收起不停止会话，也不改变这段会话正在哪条路径里继续。

体验样例：#12“确定活动形式”最初没有会话；用户从票下开始讨论，随后从一条消息分别探索“观影”和“桌游”。两条方向仍在同一张票下。票与票之间表达依赖，会话之间表达分叉；分支不各自获得票据完成状态，结束聊天也不代表原票解决。

2026-09-10 用户进一步选择改造 B，放弃 A 的大容器和 C 的路径布局。保留 B 的平铺画布，票据下可以挂出会话，也可以收进票里，从票据进入讨论；“票据是上层工作单元”不要求外面再套一层区域。

本轮 B 原型已加入票据卡上的开始／继续入口：空票先建立样例会话、准备引用，等用户发送；已有会话可在票下展开，或收起后从票内继续。两种展示共用同一份会话，不因收起或展开创建副本。浏览器已走通“空票 → 开始讨论 → 分叉 → 收起后继续”。2026-09-10 用户体验后以“对味了”认可改造方向，采用此版作为后续交互设计基线；具体尺寸和动效参数不因此冻结。当前仍是内存样例，未接入实际 Pi 或 tracker。见[实验记录](../../apps/web/experiments/canvas-space/README.md)。

### 总画布与 Wayfinder 入口

总画布可承载从 `grill-with-docs` 开始的澄清讨论及其真实分叉，也可承载普通聊天；grilling 是提问方法，不规定根节点名称。用户觉得目标需要更系统地跨会话探索时，可以主动创建 Wayfinder 地图；产品不按节点数或对话内容自动触发。原讨论与来源关系保留，既有分叉不批量改成工单。Wayfinder 地图的展开或收起布局仍待验证，技能选择边界见 [ADR 0004](../adr/0004-canvas-carrier-and-user-chosen-skills.md)。

### 缩略图与轻量说明

右下角放画布缩略图，展示节点分布、当前视野与所在位置；点击位置移动画布视野。旁边提供小问号，可打开方法说明或重新查看已关闭的提示。

小卡片与就地说明使用从 Matt 文章整理、保留出处的短文案。按明确的 skill 入口或用户操作展示，不根据聊天内容推断用户困惑。相关入口首次提示，用户可关闭、主动重开；不抢焦点，不在每轮重复弹出。例如：“不知道也可以直接说；需要看过才能判断时，可以先做个小样。”提示不发送给 Agent，不写入票据，也不改动 Matt skills。

缩略图、连线、发光和提示都是展示层行为；它们不自动打开下一段讨论或触发分支上下文交接。

### Wayfinder 决策票全部关闭时的提示（已确认）

当一次成功读取确认某张 Map 的完整子票集合非空、且全部已关闭时，在 Map 旁展示一条可关闭的小提示，帮助用户检查是否可以结束探索。不能只统计当前视野内的节点或叶子节点；来源读取不完整、状态未知时不触发。提示依据票据记录，不分析聊天上下文。

建议文案：“这张地图的决策票都已关闭。可以检查一下：还有未澄清的问题吗？通往目的地的路是否已经清楚？”补充说明：“如果目的地是形成方案，可以主动使用 /to-spec；也可以确认决策，或按原定目的地选择下一步。”

提示可提供“查看地图”入口，让用户查看 Destination 与 Not yet specified；查看不发送消息。全部关闭只是检查时机，不是地图完成的证明，取消或移出范围也不计为成功结论。不自动调用 skill、创建 Spec、关闭 Map 或继续下游工作。提示不抢焦点，关闭后不因重复刷新再次弹出，可从轻量说明入口重新查看。

体验验证：最后一张票关闭后出现检查提示；仍有迷雾或存在取消票时，不宣告地图完成；目的地为锁定决策时，不强制推荐生成 Spec；关闭提示、查看地图和刷新均不改变会话或 tracker。此项已接入主画布（票 #11），试跑记录见 [地图结论与产物](../research/map-conclusions-results.md)。窄屏摆放仍需实际体验验证。

## 关系与解锁

票据依赖及状态以 tracker 为准。Agent 成功修改来源后，Waygoal 通过既定通知与读取方式取得记录，更新关系和相关节点状态；直接在外部 tracker 修改，需要后续读取核对，不承诺即时同步。

解锁需要取得依赖关系和各前置票据状态。一个下游同时依赖 A、B 时，仅 A 满足前提还不能解锁；全部前提满足后才变为可推进，下游自身仍未完成。关闭聊天面板不等于关闭票据；来源读取失败或关系未核对不能当成“没有阻塞”。来源关系变化或前置重新打开后，依据新取得的记录重新判断。

保留关闭原因：解决问题、取消和移出范围不能统一画成成功。分支来源与阻塞依赖含义不同，不能因为线相连就推断解锁。

## 缓慢点亮

| 已知状态或变化 | 视觉方向 |
| --- | --- |
| 等待前提 | 清楚的轮廓，较弱的光 |
| 从阻塞变为可推进 | 边缘缓慢亮起一次，提示这里可以继续 |
| 当前所在节点 | 明确的聚焦边框，标示当前位置 |
| 已有结论 | 留下稳定的暖光 |
| 取消或移出范围 | 淡出当前路径，保留可回看记录 |

位置与工作状态可以同时表达，例如用户可以正在查看一个等待前提的节点。光效旁保留简短状态文字；重复刷新同一状态不重复播放解锁效果。光效的颜色、强度和时长仍需实际体验选择。

主 Map 随已有结论逐渐呈现更多亮点；整体完成态根据来源地图及其结论反映的目的地是否达到、必要问题是否已有结论呈现。不能用叶子节点全部关闭或一个关闭百分比替代这个判断，也不能由动画反向关闭地图。探索完成后的下一步由用户按 Destination 选择，可以是汇总方案、确认决策或其他交接，不宣称实际目标已经交付。

## 验证与当前限制

### 返回与成果回看

除画布定位外，已认可的探索方向还包括分支带结论返回，以及从方案回看依据。交接由用户或其已调用的方法发起，画布呈现来源和已有记录；具体布局与阶段衔接尚待真实使用验证。

体验验证：发起交接后，原讨论能使用分支结论并保留用户原有约束，无需用户重复解释或手动搬运；从方案中的关键内容能回看相关讨论、决定或研究，并检查具体要求是否准确保留。跨领域产物可以是 Spec、创作简报或活动方案，不因展示需要强制采用工程执行步骤。结果与约定标准支持继续、修改或停止，关闭票据本身不代表实际成果已获认可。

### 位置、状态与实现边界

体验验证：用户能从缩略图找到位置，辨别“等待”“解锁”“已有结论”，理解一项完成影响了哪里；关闭提示、移动视野和刷新状态均不改变聊天消息。

最小状态样例：下游依赖 A、B；只完成 A 时保持等待，完成 B 后解锁但不完成下游；重复读取不重放解锁，重新出现阻塞时显示等待。地图中有取消票据时，不将其表现为成功结论或据此自动完成主 Map。

现有 Pi UI 已有树导航和分叉入口，但树导航会切换实际活动路径。2026-09-10 起（票 #3）只读查看与继续已经分开：查看来源或兄弟路径走只读历史读取，不调用树导航、不新增消息；在这条路径上发送消息才移动活动路径，发送本身就是那次明确选择，没有单独的确认按钮。真实分叉在主画布上可感知：节点显示分叉来源与会话内分叉数量，选中节点下方列出会话内路径，跨会话来源用连线指向来源节点。来源同时记会话与消息位置；只有 Pi header 可依据时，照实说明只知道来源会话。试跑记录见 [branch-navigation-results.md](../research/branch-navigation-results.md)。2026-09-10 起 `/waygoal` 是不带固定 Wayfinder 根入口的真实会话画布（票 #2：发现、新开、拖动、平移缩放、按工作目录恢复）；旧票据入口曾移到 `/beacon/tickets`，票据讨论接入（票 #8）后于 2026-09-11 删除。

2026-09-11 实现状态核对：主画布已复用宿主的手动改名和标题生成入口（票 #5），也已接入标题查找、最近讨论、缩略图、手动分组和关联（票 #6）。命名由用户主动触发；同一会话内的各条路径尚无独立命名体系。试跑记录见 [起名字与找回讨论](../research/find-and-rename-results.md) 和 [分组与关联](../research/groups-and-links-results.md)。

本地票据依赖变动与一次性解锁提示已接入（票 #9）；地图原文、产物链接和票据全部关闭后的检查提示也已接入（票 #11）。远程来源支持已取得的 GitHub 原始结果与离线样本（票 #10），尚无外部来源主动监听或任意 tracker 格式适配。上述完整光效方案、分支带结论返回和从方案回看依据，仍需单独做真实体验验证。跨 tracker 通知与读取的边界见 [ADR 0001](../adr/0001-tracker-authority-and-local-canvas-records.md)。

### 2026-09-16 · 入口与控件收整

- 用户明确要求所有 UI 有一致的设计，不以“按钮能用”作为完成标准。当前一轮统一画布选择、轮次卡片与聊天面板，视觉验收仍需真实操作反馈。
- 画布切换使用紧凑列表；不再把 `main` 展示为特殊的“主画布”，已有默认归属在界面称为“未归类会话”。兼容记录与会话归属保持原样。目录切换和加入会话分别进入菜单子页。
- 新建直接打开空白输入框，不先要求命名。当前实现以可区分的“画布 N”命名；发送后自动命名、编辑画布名称仍未实现。入口对比原型的临时标题行为不能当作产品能力。
- 桌面聊天面板固定右下角，左边、上边和左上角可拖动改变大小；尺寸保存在浏览器本地。双击把手或聚焦后 Home 恢复默认，方向键可微调。尺寸随可用空间限制，窄屏回到自适应布局；拖拽不重建聊天组件。
- 轮次卡片使用单层选中边界；编号、标题、回答按垂直阅读顺序排版。上下文工具条按按钮数量收窄并靠近卡片，桌面按钮 32px，触控至少 44px；分叉不可用时提供原因提示。
- 入口的三个对比布局保存在 `codex/prototype-canvas-entry-20260916`（`4a34441`），可运行 `npm run prototype:entry`。只使用内存样例，尚未完成布局选择的体验验收。

- 顶部导航保留自身的边框、底色与阴影；桌面端绝对定位于画布上方，不占用整行布局高度。聊天框可向上拉到窗口顶部附近（保留 12px 边距），不受导航高度限制；窄屏仍保留正常导航与内容顺序。

### 同一画布中的会话收放

会话总览与轮次不再是两个递进视图。新进入的已有会话默认是收起卡片；点击在原位置展开真实轮次，并在右侧打开连续聊天。可以同时展开多段会话，其他会话仍留在同一坐标空间。收起只隐藏该会话的轮次，不关闭聊天、清除草稿或改变 Pi 路径；展开状态按画布保存。

展开时为轮次让出空间，周围会话临时避让；收起后恢复原来的收起布局。展开后的跨会话关系仍指向具体轮次，折叠的端点指向会话卡。查找、票据与整理工具按需打开，不替换画布。缩略导航展示会话、可见轮次、关系与当前视野，居中留出边距；点击只移动镜头。

### 轮次所得与语义缩放

第一步实现为三个阅读层次：近景显示问题与回答预览（有所得时显示所得），中景突出所得、尚无所得则保留问题，远景呈现连接和节点标记。当前节点与已确认所得有不同标记；点击远景节点回到可读比例并只读定位原文。缩放不重排卡片，不改变 Pi 路径或右侧草稿。阈值留有回差，避免临界比例反复切换。

选中卡片后的“所得”打开一句话编辑。用户可以直接记录，也可以主动“请 Pi 提炼”：沿用该会话的模型与传输设置，只提供这一轮问题和回答，不提供工具，不写入 Pi 历史。打开画布或缩放不会自动批量调用模型。模型生成先保存为待确认；用户可改写后确认，或删除所得。

所得按画布和轮次保存，属于展示注释，既不替换原文，也不会自动带入下一轮上下文。确认只表示用户认可这句记录，不表示任务完成或票据关闭。原文指纹变化后显示“原文已变化”，不再显示已确认标记；保存失败保留编辑文字。后续接入的多选综合、选文探索与材料托盘见下文 ThoughtDAG 借鉴落地部分。


### 2026-09-17 · 主画布动效手感

本轮实现服务于“保持方向”：点击定位用 240ms 镜头过渡，直接拖动、滚轮和键盘不添加缓动。移动中抓住画布，从当下可见位置开始拖动；松手后再次点击定位恢复过渡。轮次拖动只接受发起手势的指针，避免第二个触点夺走控制。

按钮使用 120ms 的轻按压；上下文工具条、关系预览、所得编辑与聊天面板用 160ms 淡入。首次输入框移到右侧缩短到 240ms，只平移、不拉伸正文，输入或再次操作可以结束该过渡。取消轮次卡片反复挂载的位移和整张画布的 420ms 入场，运行状态保留稳定标记。键盘操作不播放转场；减少动态效果保留淡入与颜色反馈，位置直接更新。

自动验证覆盖镜头过渡中抓取、跟手平移、滚轮、键盘与减少动态效果，并沿用连续聊天与真实 Pi 分叉验收。动画的主观节奏和真实触屏手感仍需实际体验确认。


### 2026-09-17 · 操作与结果的空间反馈

补充四个已授权场景，分别帮助保持方向和验证结果：

- 真实 Pi 分叉成功后，新分支标题／内容面从来源方向轻移淡入 240ms，来源连线淡入 160ms。卡片边界和连线端点始终位于同一套最终几何位置；已有共享历史不重复入场。
- 明确展开会话时，新轮次淡入 120ms；收拢时只保留 120ms 不可聚焦、不可点击的视觉残影。小于 24 屏幕像素的避让用 120ms 平移，仅当连线两端同向同量移动时连同线一起移动；较大重排或跨越固定端点的组件直接落位。
- 引用快照成功返回后，新增材料轻移淡入 160ms；移除立即更新下一轮发送材料，仅独立的不可交互残影淡出 120ms。恢复已保存引用不重播。
- 用户确认所得且保存成功后，只让确认标记轻微缩放淡入 160ms；提炼、保存失败和重载均不播放确认反馈。

动画不负责保存、发送或改变 Pi 路径。新的指针操作、键盘输入、滚轮或减少动态效果设置变化可结束进行中的反馈；异步请求开始后发生这些操作时，不补播迟到的动效。减少动态效果保留透明度变化，不平移或缩放。所有参数复用现有主题 token，无新增动效依赖。

### ThoughtDAG 借鉴落地：选文探索与综合材料

本轮补齐“理清想法 → 分叉探索 → 带回材料”的入口，沿用连续聊天和当前视觉，不引入新的模型运行器。

- **选文探索**：在一条已保存的回答中选文，点“分叉探索”先打开带引文的提问框；发送时才从这条回答创建真实分叉并经宿主发送。关闭不创建会话，不动主线草稿和待发送材料。跨消息选区不提供分叉入口。新分支发送被明确拒绝时，由宿主保留问题供重试，不再次分叉。
- **材料托盘**：紧邻输入显示“本次额外带入”，按份展示来源会话、问题或轮次身份、选取范围、原文和取得时间，可移除及只读查看来源。文本字符量仅计所选原文，不是 token 预算，更不代表 Pi 的完整上下文。来源读不到时仍保留已取得原文。
- **多选综合**：通过“画布操作 → 多选轮次”进入点选模式，或用 `⌘/Ctrl` 点击轮次。可选整轮文字、回答或用户消息；“加入材料，继续综合”仅批量加入当前会话托盘，保留草稿，由用户填写综合目的后正常发送。全部来源读取成功且目标路径一致才提交，失败保留选区；切换目标或取消后不接收迟到结果。原讨论、分叉和布局不因此改写。
- **异步操作边界**：回源读取遇到更新的手势或键盘操作即取消定位；批量材料返回不抢走其他输入框的焦点。离开分叉发起位置后，旧结果只保留真实分叉及未发送问题，不自动切回或发送、不禁用新会话输入。后台画布写入不更改工作区当前画布。已创建分叉而载入失败时，当前页面重试复用其 ID；提前打开它并写了新草稿时，恢复问题与新输入合并，不覆盖。选文浮层优先处理 Escape，关闭它不同时停止生成。
- **范围边界**：第一版批量综合面向已有当前会话，不自动新建综合会话；没有框选手势、PDF 阅读器、来源版本比较或完整请求检查器。未发送文字与材料沿用会话／路径内存恢复，不承诺跨刷新草稿保存。已发送材料仍作为真实轮次的来源快照持久保留。

体验验收继续以“主线留草稿 → 从回答分叉深入 → 返回 → 合用两条分支材料 → 回看依据”为准。自动套件覆盖不代替真实模型、长材料及触屏手感验收。

### 票据的真实归属与布局（2026-09-20）

- GitHub 仓库是来源信息，不占画布卡片。带 `wayfinder:map` 标签的真实 issue 保留自己的 ID、正文与讨论，作为 Map Ticket 展示。
- 父子关系来自 GitHub 原生 parent/sub-issues，实线表示包含；原生 blocked-by 与正文中已有依赖共同显示，虚线表示前置条件。共享仓库或相似标题不构成归属关系。
- 交付 GitHub 票据后，用宿主的 `gh` 登录态只读取得关系；已有票据可在详情中手动刷新。画布轮询只读缓存，读取失败保留上次关系并显示失败原因，不把失败当成“没有关系”。正文和关系分别标注取得时间。
- 展开的会话保留完整占位，票据按真实家族避让。来源信息不进入查找、缩略图和视野边界。“画布工具 → 整理会话与票据 → 整理票据”按归属重新排列，支持撤销；普通查看不会重写用户坐标。
- 票据预览取 `Question`，Map Ticket 取 `Destination`。聊天卡片在截短前收拢 Pi skill 的完整展开文本、缩短文件引用路径；原始历史及引用材料不变。

### 票据速览与集群

- 票据详情优先展示来源中的目标、问题、结论，以及可点开的子票据和依赖；正文按已有标题排版，不生成模型摘要。补充说明、相关资料、来源同步信息和完整原文按需展开。
- Map Ticket 与真实父子关系中的后代构成带标题的外框；本地地图以其地图文件为根。共享 GitHub 仓库本身不构成集群。
- 拖动外框标题栏整体移动票据、关联会话和轮次，方向键微调；点击独立箭头收起或展开。收起后移动也会更新隐藏成员的坐标。收起保留总票据与数量，隐藏子票据、其关联会话与展开轮次及连线。外框包含实际关联的会话范围；同组会话不是票据的外部避让障碍。定位当前对话会重新展开所属集群。坐标、讨论归属和右侧会话不变，展开恢复原位置。收起状态按画布保存。

- 集群外框负责整组移动和收起；总 Map 直接作为容器，直属票据以空间归属表达包含关系。依赖线带箭头，方向为前置票据 → 依赖它的后续票据，随卡片相对位置选择上下或左右接入边。手动关联不声明方向。

### Map 容器（2026-09-20 更新）

- 外框本身代表总 Map，不再在内部重复放置总 Map 卡片或绘制它到直属票据的包含线。嵌套票据的实际父子关系保留。
- 点击容器标题查看 Map 详情；拖动标题栏整体移动票据及关联讨论，右侧独立箭头展开、收起。Map 讨论从标题栏入口或详情开始。
- 收起为 Map 摘要，显示下属票据数量、已完成数量与讨论数量；展开恢复原位置。已取消票据不计入已完成。
- 依赖继续用前置票据指向后续票据的虚线箭头；手动关联不声明方向。

### Map 信息与状态可读性

- 展开时标题完整换行，下方展示来源目标、票据完成数量和依赖方向说明。实际标题栏高度参与边界和避让，不能盖住相邻 Map。
- Map 本身的讨论在标题下以具名入口展示，点击打开右侧会话；独立开关展开或收起轮次。展开后的会话仍属于同一容器；不再画标题到会话的冗余长线。
- 完成数与卡片共用真实 `resolved` 状态。完成票据使用更深的青色背景、勾选图形与“已完成”文字；缩略状态保留文字标记。取消不计为完成。
- 依赖线从可见票据及讨论入口边缘出发，指向后续票据边缘，优先使用卡片间有空隙的方向。重复关系标签放入容器说明，避免与线和卡片重叠。

### Map 字体与讨论归属

- Map 保留现有中西文字体。标题、目标正文、操作和元信息分为 22 / 16 / 14 的阅读层级；50%–100% 画布缩放之间补偿字号，在 60% 缩放时保持对应的屏幕阅读尺寸。低于 50% 进入远景，文字继续随画布缩小；浏览器缩放不受限制。
- 目标说明限制阅读行宽，标题可换行；文字变化后的真实高度纳入 Map 边界与相邻家族避让。
- Map 根票据关联的每个会话及其展开轮次带有“Map #编号 的讨论”分区，范围跟随内容和拖动变化。折叠轮次后仍保留归属；整体收起 Map 时一并隐藏。票据依赖不进入讨论分区。


### 2026-09-20：画布缩放与标记相关

- 触控板在画布上的捏合只缩放画布，取消 Ctrl+wheel 的浏览器默认缩放，避免导航、聊天标题和输入框被整页放大裁掉。画布外仍保留浏览器缩放。工作区按 Visual Viewport 的可见范围布局，兼容已经放大、偏移的页面与软键盘。
- 轮次操作“标记相关”用于记下两轮讨论之间的联系，方便回看对照。它不创建 Pi 分叉，不切换当前会话，不把内容送入 Agent。
- 从卡片操作开始时已选中来源；从画布工具开始时先选来源。接着直接点目标卡片，不再要求寻找连线小圆点。当前来源高亮，说明区显示下一步和取消入口，Escape 只退出关联选取。
- 保存成功后退出选取并反馈“已标记相关”。重复选择同一对卡片保留已有关系；删除需点击连线后选择“移除关联”。保存失败保留来源并提供重试说明。

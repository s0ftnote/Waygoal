# 画布导航、轻量提示与状态变化

已确认的展示方向；本文件不代表主原型已完成实现。服务于“保持方向”，沿用 Pi 聊天，不将 grilling 改造成问题卡或可操作草图。

## 设计重心

交互、视觉与动效是产品的主要投入方向。画布承载 Pi 会话及可选票据，方法沿用原始 skills；不通过另加流程干预创造差异。

优先打磨三个实际动作：从讨论中分出一条新路径、打开节点后回到整体、辨认工作记录发生的变化。动效连接操作前后的位置与关系，使用户看懂“从哪里来、到了哪里、什么变了”。分叉生长、展开收起、镜头移动与缓慢点亮是可试验的表现形式，不是已经定稿的动画方案。

交互优先于动画完整播放：用户可继续操作，阅读焦点保持稳定，减少动态效果时仍能通过位置、连线和文字理解相同信息。动画展示已发生的操作或已取得的来源状态，不制造进度、不触发工作流。用真实分叉与返回样例验证方向感，再调整具体布局、节奏和视觉细节。

## 导航与说明

### 工作区与多画布（已确认）

用户可以在当前工作区新开画布，也可以切换工作区。工作区以工作目录为基础，一张画布可以有多个互不相连的讨论起点；不要求所有讨论共享一个总目标。新开画布与切换工作目录是不同操作，新画布不隐含建票或调用 skill。

体验验证：用户在同一工作区分别建立“产品”和“活动”画布，能够切换并恢复各自的节点布局和位置；切换到另一工作区时，清楚知道当前使用的工作目录。入口布局通过原型验证。

### 独立会话、标题与手动整理（已确认）

没有关联的会话是正常的独立节点。用户不必使用 Matt skills、创建票据或整理连线才能聊天；会话管理的主要入口是画布，不另设传统会话列表作为主界面。

- **标题识别：** 会话节点直接展示 Pi 保存的会话标题，支持用户请求生成标题或手动改名，供扫视与搜索定位。用户手动命名后，不因继续聊天或刷新而自行覆盖；再次生成仍由用户发起。没有名称时用首条消息的简短片段等已有内容作显示回退，不把回退文本当成已保存标题。
- **自由摆放：** 用户可拖动节点，位置稳定保留；新会话出现在容易发现的位置。星系是视觉意象，不使用随机散点和持续漂移承担管理工作。
- **分组：** 框选若干节点，圈成一组并起名；缩小时看组名，展开后看节点。整理只改变画布记录，不新建会话或改动聊天内容。
- **手动关联：** 用户按需连接节点，可附一句说明。它表达“我认为有关”，不修改真实分叉来源、合并上下文或创建 tracker 依赖；删除手动关联只取消该联系。
- **找回内容：** 提供标题搜索定位、最近访问和回到当前会话的快捷入口，避免靠记住坐标寻找会话；这些入口的具体形式通过原型验证。

关系的来源必须能辨认：真实分叉来自 Pi 操作，票据依赖来自 tracker，手动关联来自用户整理。分组名称由用户维护；票据节点取票据标题，关联会话仍保留自己的名称，不因会话改名修改原票据。具体线型和展开样式待验证。

体验样例：三个独立会话“活动海报”“场地预算”“开场音乐”被圈为“周末聚会”；用户把“活动海报”改名为“给老朋友的邀请”，已有位置、分组和连线保持不变，并能通过新标题找到它。将“开场音乐”与海报手动关联后，两个会话仍保留各自历史，票据依赖没有变化。

### 真实分叉（已确认要做）

直接服务于“保持方向”：用户能发现分叉入口，知道从哪条消息分出，并看清当前讨论路径。以下是首轮实现与体验验证的要求，具体排版尚未确定：

- 在可分叉的位置提供清楚的“从这里分叉”操作，产生后显示来源连接、原路径与新路径，并标明当前继续的位置。
- 区分“查看这段历史”与“在这里继续说”。查看只改变展示；在某条路径上发送消息才切换实际对话路径。回到来源不自动合并分支结论，带结论返回另行发起。
- 默认呈现真实分叉处及可识别的内容预览，连续消息可以收起；不为每条消息或每轮 grilling 自动创建独立节点或票据。
- 普通 Pi 会话也具备这些能力。只有关联了真实票据，才显示由来源记录支持的依赖与完成状态。

最小体验样例：在同一问题处分别探索 A、B，用户能看见共同来源、识别当前路径、只查看另一条路径，再明确选择继续。整个过程不需要安装 Matt skills 或创建 tracker；查看动作不改变 Agent 的活动路径，也不自动发送消息。

### 票据在上、会话在下（已确认）

有票据的部分以票据作为进入讨论的上层入口，按 [ADR 0003](../adr/0003-discussion-and-ticket-map.md) 的层级呈现：

- **打开票据**：看问题、状态和票据下面的会话。
- **尚无会话**：提供“开始讨论”，用户点击后按需创建关联会话。Wayfinder 票据可准备对应调用和准确票据引用，由用户发送；查看或展开本身不发送消息。
- **已有会话**：提供继续讨论入口；有多个会话或分支时展开选择，不凭票据状态替用户选定路径。
- **收起票据**：收起下层讨论，票据仍留在画布，保留讨论数量和可识别的展开入口；收起不停止会话，也不改变这段会话正在哪条路径里继续。

体验样例：#12“确定活动形式”最初没有会话；用户从票下开始讨论，随后从一条消息分别探索“观影”和“桌游”。两条方向仍在同一张票下。票与票之间表达依赖，会话之间表达分叉；分支不各自获得票据完成状态，结束聊天也不代表原票解决。

2026-09-10 用户进一步选择改造 B，放弃 A 的大容器和 C 的路径布局。保留 B 的平铺画布，票据下可以挂出会话，也可以收进票里，从票据进入讨论；“票据是上层工作单元”不要求外面再套一层区域。

本轮 B 原型已加入票据卡上的开始／继续入口：空票先建立样例会话、准备引用，等用户发送；已有会话可在票下展开，或收起后从票内继续。两种展示共用同一份会话，不因收起或展开创建副本。浏览器已走通“空票 → 开始讨论 → 分叉 → 收起后继续”。2026-09-10 用户体验后以“对味了”认可改造方向，采用此版作为后续交互设计基线；具体尺寸和动效参数不因此冻结。当前仍是内存样例，未接入实际 Pi 或 tracker。见[实验记录](../../apps/web/experiments/canvas-space/README.md)。

### Grilling 轮次（未决）

用户提出将一波一波的问题可视化，尚未确定形式。目前建议先验证真实分叉，再观察连续长讨论是否需要轮次标记。若试做轮次标记，应作为原对话中的回看位置，与真实分叉及票据区分；不恢复已撤回的问题卡交互，不通过分析上下文制造工作关系。轮次如何划分、由谁标记仍未决。

### 总画布与 Wayfinder 入口

总画布可承载从 `grill-with-docs` 开始的澄清讨论及其真实分叉，也可承载普通聊天；grilling 是提问方法，不规定根节点名称。用户觉得目标需要更系统地跨会话探索时，可以主动创建 Wayfinder 地图；产品不按节点数或对话内容自动触发。原讨论与来源关系保留，既有分叉不批量改成工单。Wayfinder 地图的展开或收起布局仍待验证，技能选择边界见 [ADR 0004](../adr/0004-canvas-carrier-and-user-chosen-skills.md)。

### 缩略图与轻量说明

右下角放画布缩略图，展示节点分布、当前视野与所在位置；点击位置移动画布视野。旁边提供小问号，可打开方法说明或重新查看已关闭的提示。

小卡片与就地说明使用从 Matt 文章整理、保留出处的短文案。按明确的 skill 入口或用户操作展示，不根据聊天内容推断用户困惑。相关入口首次提示，用户可关闭、主动重开；不抢焦点，不在每轮重复弹出。例如：“不知道也可以直接说；需要看过才能判断时，可以先做个小样。”提示不发送给 Agent，不写入票据，也不改动 Matt skills。

缩略图、连线、发光和提示都是展示层行为；它们不自动打开下一段讨论或触发分支上下文交接。

### Wayfinder 决策票全部关闭时的提示（已确认）

当一次成功读取确认某张 Map 的完整子票集合非空、且全部已关闭时，在 Map 旁展示一条可关闭的小提示，帮助用户检查是否可以结束探索。不能只统计当前视野内的节点或叶子节点；来源读取不完整、状态未知时不触发。提示依据票据记录，不分析聊天上下文。

建议文案：“这张地图的决策票都已关闭。可以检查一下：还有未澄清的问题吗？通往目的地的路是否已经清楚？”补充说明：“如果目的地是形成方案，可以主动使用 /to-spec；也可以确认决策，或按原定目的地选择下一步。”

提示可提供“查看地图”入口，让用户查看 Destination 与 Not yet specified；查看不发送消息。全部关闭只是检查时机，不是地图完成的证明，取消或移出范围也不计为成功结论。不自动调用 skill、创建 Spec、关闭 Map 或继续下游工作。提示不抢焦点，关闭后不因重复刷新再次弹出，可从轻量说明入口重新查看。

体验验证：最后一张票关闭后出现检查提示；仍有迷雾或存在取消票时，不宣告地图完成；目的地为锁定决策时，不强制推荐生成 Spec；关闭提示、查看地图和刷新均不改变会话或 tracker。此项为已确认设计，尚未接入主画布。

## 关系与解锁

票据依赖及状态以 tracker 为准。Agent 成功修改来源后，Waygoal 通过既定通知与读取方式取得记录，更新关系和相关节点状态；直接在外部 tracker 修改，需要后续读取核对，不承诺即时同步。

解锁需要取得依赖关系和各前置票据状态。一个下游同时依赖 A、B 时，仅 A 满足前提还不能解锁；全部前提满足后才变为可推进，下游自身仍未完成。关闭聊天面板不等于关闭票据；来源读取失败或关系未核对不能当成“没有阻塞”。来源关系变化或前置重新打开后，依据新取得的记录重新判断。

保留关闭原因：解决问题、取消和移出范围不能统一画成成功。分支来源与阻塞依赖含义不同，不能因为线相连就推断解锁。

## 缓慢点亮

| 已知状态或变化 | 视觉方向 |
| --- | --- |
| 等待前提 | 清楚的轮廓，较弱的光 |
| 从阻塞变为可推进 | 边缘缓慢亮起一次，提示这里可以继续 |
| 当前所在节点 | 明确的聚焦边框，标示当前位置 |
| 已有结论 | 留下稳定的暖光 |
| 取消或移出范围 | 淡出当前路径，保留可回看记录 |

位置与工作状态可以同时表达，例如用户可以正在查看一个等待前提的节点。光效旁保留简短状态文字；重复刷新同一状态不重复播放解锁效果。光效的颜色、强度和时长仍需实际体验选择。

主 Map 随已有结论逐渐呈现更多亮点；整体完成态根据来源地图及其结论反映的目的地是否达到、必要问题是否已有结论呈现。不能用叶子节点全部关闭或一个关闭百分比替代这个判断，也不能由动画反向关闭地图。探索完成后的下一步由用户按 Destination 选择，可以是汇总方案、确认决策或其他交接，不宣称实际目标已经交付。

## 验证与当前限制

### 返回与成果回看

除画布定位外，已认可的探索方向还包括分支带结论返回，以及从方案回看依据。交接由用户或其已调用的方法发起，画布呈现来源和已有记录；具体布局与阶段衔接尚待真实使用验证。

体验验证：发起交接后，原讨论能使用分支结论并保留用户原有约束，无需用户重复解释或手动搬运；从方案中的关键内容能回看相关讨论、决定或研究，并检查具体要求是否准确保留。跨领域产物可以是 Spec、创作简报或活动方案，不因展示需要强制采用工程执行步骤。结果与约定标准支持继续、修改或停止，关闭票据本身不代表实际成果已获认可。

### 位置、状态与实现边界

体验验证：用户能从缩略图找到位置，辨别“等待”“解锁”“已有结论”，理解一项完成影响了哪里；关闭提示、移动视野和刷新状态均不改变聊天消息。

最小状态样例：下游依赖 A、B；只完成 A 时保持等待，完成 B 后解锁但不完成下游；重复读取不重放解锁，重新出现阻塞时显示等待。地图中有取消票据时，不将其表现为成功结论或据此自动完成主 Map。

现有 Pi UI 已有树导航和分叉入口，但树导航会切换实际活动路径。2026-09-10 起（票 #3）只读查看与继续已经分开：查看来源或兄弟路径走只读历史读取，不调用树导航、不新增消息；在这条路径上发送消息才移动活动路径，发送本身就是那次明确选择，没有单独的确认按钮。真实分叉在主画布上可感知：节点显示分叉来源与会话内分叉数量，选中节点下方列出会话内路径，跨会话来源用连线指向来源节点。来源同时记会话与消息位置；只有 Pi header 可依据时，照实说明只知道来源会话。试跑记录见 [branch-navigation-results.md](../research/branch-navigation-results.md)。2026-09-10 起 `/beacon` 是不带固定 Wayfinder 根入口的真实会话画布（票 #2：发现、新开、拖动、平移缩放、按工作目录恢复）；旧票据入口曾移到 `/beacon/tickets`，票据讨论接入（票 #8）后于 2026-09-11 删除。

2026-09-09 源码核对：Pi WebUI 的[生成标题入口](../../apps/web/app/api/sessions/[id]/auto-name/route.ts)调用[临时命名 Agent](../../apps/web/lib/session-title.ts)，读取会话内容生成标题后保存为会话名称；[手动改名](../../apps/web/app/api/sessions/[id]/route.ts)同样更新 Pi 会话信息。这是可复用的代码能力，本轮未实际调用模型或修改任何会话名。用户主动请求命名是明确的内容处理操作，与展示层自动分析聊天并路由或建关系不同。该能力以会话为单位，不证明同一会话内每条分支已有独立标题；分支标记的具体交互仍需验证。自由分组、手动关联及标题在主画布中的接入尚未实现。

# Tracker 保存正式工作内容，Waygoal 保存本地画布记录

Waygoal 需要在保留用户 tracker 配置的同时，恢复节点、对话和工作位置。正式票据及其关系以用户配置的 tracker 为准，聊天历史由 Pi 保存，Waygoal 持久保存本地画布记录；原文快照服务于展示和恢复，不作为可以独立修改的第二套票据。这使 Web 可以使用同一套视图，而不要求它分别接入每个平台的账号和读取接口。

Agent 成功创建、读取或修改来源票据后，通过统一通知把实际票据引用及其原文所在的文件或宿主保留的工具结果引用交给 Waygoal，由程序读取并保存快照。Agent 只维护 tracker 原票，不在通知中重新抄写或生成第二份正文。创建时可以复用成功提交的同一份正文文件；来源平台若改写了内容，应重新取得最终记录。读取已有票据时，使用实际源文件或读取工具取得的原始结果；原始结果中的正文、评论和关系仍需按其格式提取，不能把模型改写当作原文。

宿主登记稳定的节点身份并关联来源和 Pi 会话，后续复用已登记引用；创建失败不显示为正式票据，来源修改失败不显示为已同步。通过 Web 发起的内容修改仍应更新原 tracker，成功后再更新快照。外部直接修改通过后续读取核对，界面区分“最近已知内容”与“已核对当前来源”。

原文快照保留取得的正文、相关评论或结论记录及原始元数据的边界，记录来源与时间。GitHub 的答案可能在评论中，本地 tracker 的答案可能在 `## Answer` 中；只保存正文不能保证已经保存完整结论。附件默认保留来源引用，未取得的内容明确标记。票据改标题保持节点身份；重命名或迁移需核对对应关系，不能仅凭相似标题重新绑定。

## 存储位置

持久数据与插件代码安装目录分开，并按工作目录隔离。拟采用 Pi 当前用户数据目录下的 `waygoal/workspaces/<workspace-id>/`，默认示意为 `~/.pi/agent/waygoal/workspaces/<workspace-id>/`；这属于 Waygoal 的目录约定，不是 Pi 官方规定的插件数据目录。实现时跟随 Pi 的实际 agentDir，具体文件布局、工作目录迁移及存储格式尚未确定。本 ADR 不创建目录或迁移现有数据。

其中保存票据原文快照、来源/节点/会话关联与布局。tracker 选为本地 Markdown 时，正式票据仍留在用户配置的工作目录中；Pi 会话仍由 Pi 管理，只保存其关联。插件更新或重新安装不应以清理插件代码的方式删除这些工作记录。

用户创建的画布分组、分组名称及手动关联（含可选说明）也属于本地画布记录，不写成 tracker 依赖或 Pi 分叉来源。会话标题复用 Pi 保存的名称，不另维护一份画布专用名称；票据标题继续取自 tracker。改名不改变身份、关联或布局。

## 代价与验证边界

该决定接受本地副本和来源之间可能存在时间差，换取跨 tracker 的一致视图与较少的账号适配。漏报、乱序、来源变化和首次登记需要核对机制；统一通知不是对所有平台实时同步的承诺。

[通知实验](../../apps/web/experiments/tracker-notify/README.md)验证了本地源写入、真实 GitHub 只读快照、自定义格式样本、重试和引用保护。实验仍由 Agent 在通知中填写正文，尚未实现上述文件或工具结果引用读取。引用表仍由实验预设；任意 tracker 创建回执的自动登记、完整 Wayfinder 集成与持久恢复尚未验证。本 ADR 记录目标架构，不代表当前原型已经完成接入。

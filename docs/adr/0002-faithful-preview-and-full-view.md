# 预览与完整视图复用 Matt 的原始内容结构

画布需要让用户快速识别问题，同时保留深入查看的依据。采用“预览／完整视图”两种展示深度，沿用用户所用 Matt skills 及 tracker 配置的内容格式；不为卡片另造一套必须写回原票据的字段，也不把 AI 摘要覆盖为原文。代价是部分预览可能只能截取正文，而不是每张卡片都有重新润色过的文案。

## 预览内容从哪里来

| 展示内容 | 来源与维护者 |
| --- | --- |
| 标题、类型、状态 | 票据原始字段或标签；Agent 操作 tracker 后，Web 同步展示 |
| 未解决的问题 | 票据的 `Question` 原文；较长时折叠或明确截取，完整内容可打开 |
| 已有结论 | 优先使用 Agent 按 Wayfinder 写入地图索引的结论简述，并关联对应票据；没有简述时展示已取得的解决记录片段 |
| 依赖与阻塞 | tracker 中已取得的关系；未核对与明确没有依赖分开表示 |

Agent 在建票和推进工作时维护原始内容，预览随来源记录刷新，由界面选择展示哪些现有信息。Agent 不必在建票时另外维护一份独立的“卡片摘要”。原文更新后旧简述可能不再适用；关联内容需重新核对时明确标记，不能把旧简述当成已更新的结论。

完整视图展示[原文快照](0001-tracker-authority-and-local-canvas-records.md)中的完整内容并保留原来源结构：本地 Markdown 按其原格式呈现，远程正文、评论、状态和关系分别保留。页面可以折叠、排版和提供原来源入口，来源含义及原始文字保持不变；不把未取得的评论或附件宣称为完整。

## Matt 的原则与 Waygoal 的设计分别是什么

Matt 的 [Wayfinder 文章](https://www.aihero.dev/skills-wayfinder#the-map-the-fog-and-the-frontier)与 skill 规定地图作为简要索引，详细结论放在票据中，按需深入读取；也要求面向用户使用问题名称。这是两层展示的依据，但“预览／完整”界面不是 Matt 规定的 UI 模板。

文章中的冗长提问、决策疲劳和重复讨论等反馈，是整理辅助提示时的参考。提示采用预先整理的建议，按明确的 skill 入口或用户操作展示，不分析聊天上下文；它与票据内容分开，不把通用避坑建议当成节点事实，也不修改 Matt 的票据模板。小卡片与就地说明的交互边界见[画布导航与状态](../design/canvas-navigation-and-states.md)。

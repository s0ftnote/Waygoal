## Problem Statement

用户用 Pi 探索模糊想法时，讨论会不断分出方向，传统会话列表只能展示一串标题，很难说明各段讨论从哪里来、现在应该继续哪里，以及哪些结论影响后面的行动。使用 Matt Pocock 的 Wayfinder 后，更多票据、阻塞关系和跨会话探索进一步增加了迷路的成本。用户希望保留原有 Agent 和 skills 的能力，同时能把想法、讨论、决定和实际工作放在一个可理解的空间里。

Waygoal 的第一性目标是：帮助用户把模糊想法逐步变成自己认可的实际结果，并在思考、行动和调整中始终知道方向。具体体现为理清想法、保持方向、推进与验证；面向工程，也面向创意、内容和活动。

## Solution

提供通过 Pi extension 接入的本地无限画布会话空间，沿用 Pi 的会话、模型、工具和运行能力。用户从普通工作目录开始，无需导入仓库、登录 GitHub 或安装 Matt skills 才能使用基础画布。

采用用户已认可的 B 改造版交互基线：票据在总画布中平铺，票与票之间显示依赖；相关会话可以挂在票下，也可以收进票里，从票据直接开始或继续讨论。没有票据的会话独立存在。票据是上层工作单元，会话承载讨论；不额外套一个大容器来表达这一层级。

从票据开始讨论时，用户能看见会话在何处建立、准备了什么引用，以及消息何时真正发送。分叉保留来源，回看不改变继续位置。用户可以自由整理画布，通过标题、分组、缩略图和轻量状态提示找回方向。

Matt skills 保留原有流程、理念和票据格式。用户主动选择技能；Waygoal 展示既有工作记录，提供少量可关闭提示，不另加自动路由、聊天内容诊断或流程编排。方案汇总、拆解、执行和验证仍由用户与所调用的方法推进。

## User Stories

1. 作为用户，我希望选一个普通工作目录就能开始，以便不必先创建或导入 Git 仓库。
2. 作为用户，我希望切换工作区，以便区分不同目录中的工作。
3. 作为用户，我希望在一个工作区创建多张画布，以便分别整理不同主题。
4. 作为用户，我希望画布容纳多个互不相连的起点，以便不必为所有想法先找一个共同目标。
5. 作为普通 Pi 用户，我希望不用 Matt skills 或 tracker 也能新建和继续会话，以便直接使用非线性聊天空间。
6. 作为用户，我希望当前工作区已有的 Pi 会话可以在画布中找到，以便原有历史不因换界面丢失。
7. 作为用户，我希望会话标题直接出现在节点上，以便扫视时知道各段讨论在聊什么。
8. 作为用户，我希望手动修改会话标题或主动请求生成标题，以便维护自己能理解的名称。
9. 作为用户，我希望改名后仍保留原会话、位置和关联，以便名称调整不会打乱整理成果。
10. 作为用户，我希望拖动画布、缩放和摆放节点，以便自己组织思路。
11. 作为用户，我希望把若干节点圈成一个有名称的分组，以便整理相关内容。
12. 作为用户，我希望手动关联节点并附一句说明，以便留下我认为它们有关的理由。
13. 作为用户，我希望手动整理不会改变真实分叉或票据依赖，以便视觉组织不会偷偷改变工作事实。
14. 作为用户，我希望通过标题搜索、最近访问和当前位置快捷入口找回会话，以便不必记住每个节点的坐标。
15. 作为用户，我希望明确看到从某条消息分叉的入口，以便探索不同方向。
16. 作为用户，我希望分叉后看到共同来源、原路径和新路径，以便知道自己从哪里出发。
17. 作为用户，我希望在一条路径继续聊天时保留其他路径，以便不同尝试不会相互覆盖。
18. 作为用户，我希望只读回看另一条路径，以便比较内容时不切换 Agent 的实际继续位置。
19. 作为用户，我希望明确点击“从这里继续”后才切换继续位置，以便下一条消息发送到我选择的路径。
20. 作为用户，我希望能从分支回看来源，以便接回原来的思路。
21. 作为用户，我希望导航不会自动把分支结论写入另一段聊天，以便掌握上下文交接的时机。
22. 作为用户，我希望一段会话内部的真实分支也可被辨认，以便原生 Pi tree 的历史不会被误当作多个独立会话。
23. 作为使用 Wayfinder 的用户，我希望实际创建的地图与票据出现在画布上，以便把工作记录和讨论放在一起理解。
24. 作为用户，我希望票据即使尚无会话也能存在，以便先看清问题再决定是否开始讨论。
25. 作为用户，我希望空票直接提供“开始讨论”，以便无需另开聊天再手动寻找票据。
26. 作为用户，我希望开始票据讨论时只准备必要的技能调用和准确引用，等我发送，以便控制真正开始工作的时机。
27. 作为用户，我希望重复打开同一张票或快速连点时不会重复建会话或重复发送启动消息，以便避免重复工作。
28. 作为用户，我希望从票据继续上次明确记录的会话，或选择另一条讨论，以便保留工作位置又能自由切换。
29. 作为用户，我希望一张票能承载多个会话和分支，以便围绕同一个问题尝试不同方案。
30. 作为用户，我希望票下会话能挂出来，也能收进票里，以便在整体关系与局部讨论之间切换。
31. 作为用户，我希望收进票里后仍能直接继续原会话，以便不用先把所有节点展开。
32. 作为用户，我希望分叉不会复制票据或新增阻塞关系，以便讨论的分支不被误当成新的工作任务。
33. 作为用户，我希望票据标题、类型和状态可辨认，以便知道现在要解决什么问题。
34. 作为用户，我希望从票据预览打开完整原文和已取得的结论，以便查阅依据而不是只相信一段卡片摘要。
35. 作为用户，我希望预览沿用原文内容，缺失的评论或附件有明确说明，以便知道当前究竟取得了哪些信息。
36. 作为用户，我希望使用本地 Markdown 或其他 tracker 时都能在相同画布中查看票据，以便不用为每个平台改变工作方式。
37. 作为用户，我希望 Agent 只维护原 tracker 的内容，以便不用再抄写一份画布正文。
38. 作为用户，我希望来源更新后看到票据内容和关系的变化，以便判断旧结论是否仍适用。
39. 作为用户，我希望看到来源快照的取得时间和待核对状态，以便不把旧副本误认成实时内容。
40. 作为用户，我希望多个前提全部满足后下游才解锁，以便不会过早推进依赖未完成的工作。
41. 作为用户，我希望阻塞的票仍可开始或补充讨论，以便先收集信息，而不把聊天本身当成解除阻塞。
42. 作为用户，我希望关闭聊天、票据解决和票据取消分别显示，以便不会把结束会话误认为工作完成。
43. 作为用户，我希望前置票重新打开或关系发生变化时，下游状态相应调整，以便画布反映新的工作条件。
44. 作为用户，我希望解锁时出现一次轻柔点亮，并保留文字状态，以便发现变化，同时不依赖动画理解进展。
45. 作为用户，我希望通过缩略图移动视野和定位节点，以便图变大后仍能找到方向。
46. 作为用户，我希望关闭或重新打开简短的方法提示，以便按需要获得帮助而不被打断。
47. 作为用户，我希望自主调用包括 ask-matt 在内的现有 skills，以便自己选择方法，保留 skills 原有工作流。
48. 作为用户，我希望从已有结论和行动记录回到相关票据、讨论与产物，以便在推进和验证时找到依据。
49. 作为用户，我希望刷新、重启或切换画布后恢复已保存的布局、关联和继续位置，以便不用重新整理现场。
50. 作为用户，我希望窄屏时可以清楚进入聊天、返回画布，并能减少动态效果，以便不同设备和视觉偏好下都可操作。

## Implementation Decisions

- **交付边界。** 实现一个本地运行、通过 Pi extension 接入的会话画布能力。复用现有 Web 宿主和 Pi 会话访问能力，不重写模型、认证、工具或会话存储。extension 连接 Pi 事件和必要的数据通知，Web 宿主负责界面与持久记录；具体本地启动封装和通信传输由实现阶段确定，不以此新增工作流职责。
- **组织模型。** 工作区基于工作目录，一工作区多画布，一画布多起点。总画布不等于 Wayfinder 地图。已有会话可发现和定位；登记默认画布时保持稳定身份，不因每次扫描重复生成节点。跨画布复用同一会话的复杂交互不在本次范围内。
- **对象与关系。** 分开维护会话、票据、画布节点及画布分组。真实分叉来源、票据关联、票据依赖和用户手动关联有明确种类，不从标题相似或空间相邻推断。票据是其关联讨论的上层工作单元；会话可以独立存在。一票可以无会话，也可以关联多个会话及其分支。
- **展示基线。** 采用认可的 B 改造版：票据平铺，关联会话可在票下呈现或收在票内。两种展示共用同一份会话与身份。展开、收起、拖动、缩略图和关闭面板不创建会话、不切换活动路径、不停止 Agent，也不修改票据状态。
- **会话与分支身份。** 复用 Pi session 身份与消息条目身份；区分同一会话中的活动叶子和新会话 fork。分叉来源记录足够恢复出发会话及对应条目，不能把复制后可能重复的条目 ID 单独当成全局身份。原型中的“所有分叉都是新会话”只是模拟，不作为 SDK 契约。
- **查看与继续。** 将当前查看位置和实际继续位置分开。优先复用已有只读历史／上下文读取接口；仅明确继续或分叉时调用 Pi 对应操作。不得为只读回看调用改变活动叶子的 tree 导航。连续问答保持在聊天内，不按消息轮次制造画布节点。
- **分叉语义。** 沿用所使用的 Pi 操作对分叉消息和草稿的真实语义，明确显示出发消息与将继续的位置。兄弟分支不自动进入当前模型上下文。已有会话内部分支应可查看和继续，不伪造新的会话文件。运行中不允许的操作沿用 Pi 限制并反馈，不静默中断任务。
- **票据开始讨论。** 建票成功后可先登记无会话的票据。用户点击开始讨论后才按需建立关联会话；针对 Wayfinder 准备精简调用和实际 tracker 引用，不附加改写其方法的长提示。草稿可编辑，发送前不出现用户消息，也不执行 skill。已有票据内容被读取、展开或恢复时不重发启动提示。并发重复的同一次开始请求应复用结果，用户明确另开讨论则允许新会话。
- **继续票据讨论。** 记录用户明确使用的票下继续位置；提供恢复该位置和选择其他会话的入口。不能依据票据完成状态、编号或标题替用户选择新路径。缺失或失效的关联应可辨认，不能静默换成另一段历史。
- **名称与整理。** 复用 Pi 会话名称及其已有的手动命名、主动生成标题能力；票据名称继续来自 tracker。不为每个会话维护另一份画布专用名称。会话内部路径可用已有消息片段标识，不额外引入自动分支命名。布局、命名分组及带说明的手动关联属于画布记录。
- **来源权威。** Pi 保存聊天；用户配置的 tracker 保存正式地图、票据、结论和依赖；Waygoal 保存身份关联、布局和带来源信息的原文快照。正式票据内容不在展示副本上独立编辑。用户从 Web 发起来源修改时，必须以来源成功结果更新快照，不显示尚未成功的工作状态。
- **统一来源通知。** 在 Agent 成功创建、读取或修改来源后，通知交付来源范围内的稳定身份、原文文件或宿主保留的原始工具结果引用，以及足以判断取得版本和内容范围的信息。程序读取原始内容，不要求 Agent 再生成一份正文。提交文件可在确认成功后复用；来源改写内容时读取最终记录。临时引用消失前完成快照读取；未读到原文时显示未同步，不将通知成功等同于完整快照。
- **来源适配。** 用一个来源通知／读取边界承接本地 Markdown 与远程来源，而不是在画布中分别登录所有 tracker。格式提取必须对应明确支持的原始记录类型；未知格式提示未支持或未完整读取。交付至少覆盖本地 Markdown、真实 GitHub 只读结果以及一个自定义 tracker 样本的相同通知契约，不承诺自动理解任意平台回执。来源账号仍由用户既有 Agent 工具配置管理。
- **身份与更新。** 来源身份包含 tracker 范围，不能只用裸编号或标题；改标题不新建票据。来源路径迁移、引用冲突和无法核对的重命名显示待核对，不用模糊匹配自动绑定。重复通知不重复建节点；过时或不能确定新旧的记录不能覆盖已确认的新状态。更新节点内容和依赖时尽量保持用户布局，不自动重排整张图。
- **原文展示。** 预览从已取得的标题、问题、原有结论简述或原文片段选取；完整视图保留用户 tracker 的原格式和来源含义。正文、评论、答案和附件的取得边界清楚，缺失不冒充完整。保留来源与取得时间，外部修改通过后续读取核对，不宣称任意平台实时同步。
- **状态计算。** 会话运行状态、当前查看位置、票据状态、阻塞情况分别维护。所有前提均已核对且满足时才解锁；未知、缺失、歧义或读取失败不按“无阻塞”处理。取消和移出范围不自动等同于解决；以来源中明确的关系更新为准。重新打开或新增依赖会恢复等待。解锁不自动启动会话、完成下游或完成地图。
- **地图和结果。** Wayfinder 地图展示来源中的目的地、决定、未明确方向与关联票据。探索收束后保留通往方案、行动和相关产物的记录入口，不依据叶子关闭比例推断用户目标已实现，也不自动触发汇总或实施。上下文交接仍由用户或所调用的方法明确发起。
- **本地持久化。** 持久画布数据跟随 Pi 实际用户数据目录，与插件代码分离并按工作目录隔离。恢复节点身份、会话关联、布局、分组、手动关联、展开状态、最近位置和原文快照；会话消息不复制成另一套权威存储。恢复视图不自动调用活动路径切换。存储格式和目录内部划分属于实现选择，不能影响这些外部行为。
- **技能与提示。** 使用用户已安装和配置的 skills，保持普通聊天入口可用；缺少方法时提供明确说明。ask-matt 由用户主动调用。提示使用预先整理、保留出处的建议，按明确入口或用户操作展示，支持关闭与重新打开；不分析聊天、不写入消息或票据、不调用模型。
- **视觉与动效。** 沿用已确认的纸白、浅青、深蓝和少量朱红主题，保持可读的状态文字和焦点。分叉、返回、收起展开用过渡帮助辨认位置；来源解锁仅点亮一次，重复快照不重放。交互不等待动画结束；减少动态效果时直接呈现最终状态。画布可以平移缩放，窄屏聊天提供明确返回入口。
- **改造已有原型。** 替换固定 Wayfinder 根入口、打开即发长提示、一票固定一会话和阻塞票不许开聊等实验规则。保留已有可复用的 Pi 会话读取、命名、分叉、运行事件和 Web 基础能力。上游传统列表中 fork 的排布规则不作为 Waygoal 的画布语义。

## Testing Decisions

以下测试边界已于 2026-09-10 经用户确认，作为本规格的验收约定。

- **主要测试边界：用户使用的画布与其宿主接口。** 尽量通过真实页面和现有公开会话操作完成整条路径，观察可见节点、消息、实际 Pi 会话及活动叶子、来源记录和重启后的恢复结果。避免分别为按钮、卡片 DOM 结构和内部辅助函数写实现镜像测试。
- **真实 Pi 与可控模型分离。** 自动回归使用隔离的真实 Pi 会话存储和 SDK 操作，模型输出使用可控替身；这样能验证消息没有被偷偷发送、兄弟路径没有混入和继续位置切换，而不依赖模型随机回答。实现完成后用用户指定的 gpt-5.6-luna 做有界真实运行核验，保留证据；真实模型试跑不能替代回归测试。
- **必要的补充边界：统一来源通知到画布快照。** 在宿主公开的通知入口输入真实源文件或原始工具结果引用，观察原文、身份、关系、状态和恢复结果。使用临时目录及可控来源响应，不为每个 tracker 或每个解析函数扩散一套 UI 测试。真实 GitHub 只读核验用于确认样本形状，回归不依赖网络可用性。
- **已有先例。** 现有 Beacon 浏览器检查已经覆盖真实会话恢复、并发打开复用、消息数不增加和布局恢复；现有来源测试覆盖相同编号跨地图隔离、未知或歧义阻塞以及实际变更只通知一次。复用这些测试方式，而不是保留其中“阻塞票禁止开始讨论”的旧预期。已有只读上下文读取和会话生命周期测试可作为活动叶子、fork 与恢复的依据。
- **无票核心路径。** 普通工作目录、无 Matt skills 和 tracker：创建会话，从同一点探索 A/B，回看来源与兄弟分支，再明确继续。断言分叉真实存在、只读动作不改变活动叶子／用户消息数、不自动引入兄弟内容；新开会话无需建票。
- **票据讨论路径。** 取得空票，查看不会建会话；开始讨论仅准备引用，发送后才写消息；重复点击不重复初始化。一票多会话／分支，挂出与收起共用同一会话，从票内继续不要求重展开。阻塞票可聊但保持阻塞，关闭聊天不改变票据工作状态。
- **来源与持久化路径。** 本地源、GitHub 原始读取结果及自定义样本通过同一通知契约生成原文快照。覆盖成功与失败、失效临时引用、重复通知、旧通知、跨 tracker 同号、标题改变、缺失评论和宿主重启。断言 Agent 无需抄写第二份正文，持久化后身份和关联可恢复。
- **依赖路径。** 下游同时依赖 A、B：仅 A 解决仍等待，两者解决才可推进；重复读取不重放点亮；前置重新打开、新增依赖、前提未知和取消均不得错误显示成功。确认解锁不会额外发送消息、启动会话或关闭地图。
- **整理与隔离路径。** 新建／切换画布与工作区，标题修改、分组、手动关联、拖动、搜索定位后刷新并重启。断言目录范围、会话身份、布局和关系隔离；删除手动关联不改变分叉来源或 tracker 依赖。缺失会话显示失效关联，不静默绑定另一个。
- **体验验收。** 用已认可的聚会样例，实际检查用户能否识别票与会话、找到开始入口、看懂来源并返回继续。核对窄屏布局、键盘可达性、减少动态效果、缩略图和状态文字；不以动画能播放或所有测试绿灯代替用户方向感。tips 关闭后仍可完成核心路径，不产生聊天消息。

## Out of Scope

- 自动选择 skill、按画布大小升级 Wayfinder、根据聊天语义诊断困惑、自动生成票据关系或自动触发下一阶段。
- 改造 Matt 的提问、票据格式、选票、汇总、研究、实施或验证顺序；把每轮 grilling 变成问答卡或新票据。
- 在画布导航中自动总结、合并分支上下文或代替用户验收成果。
- 独立于 Pi 的 Agent 运行引擎、模型认证系统、聊天权威存储，以及独立于 tracker 的第二套可编辑正式票据。
- 为使用画布要求仓库导入、GitHub 账号，或在本产品中为所有 tracker 建立 OAuth 接入与后台实时同步。
- 自动理解任意未知 tracker 格式、未经验证的无损跨 tracker 迁移，以及跨设备多人协作或云托管。
- Matt skills 的出厂安装、上游自动更新和自定义版本覆盖策略；沿用现有技能配置。本轮不据未确认的版本策略发布安装行为。
- 自动重排所有节点、持续漂浮的星系、按票种堆叠颜色、没有真实来源变化的进度动画。
- 级联删除票据与历史、复杂跨画布共享同一会话、工作目录迁移工具，以及为同一会话内各分支另建自动命名体系。
- 本 spec 的发布不包含直接实施、拆实现票或向任何实际用户会话发送消息。

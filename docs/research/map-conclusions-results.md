# 从地图结论回到讨论与产物（票 #11）试跑

日期：2026-09-10。入口：`http://127.0.0.1:30142/beacon`（`npm run dev`）。票据：[#11](https://github.com/s0ftnote/Waygoal/issues/11)，父 Spec [#1](https://github.com/s0ftnote/Waygoal/issues/1)，前置 [#9](https://github.com/s0ftnote/Waygoal/issues/9)。

## 结论

打开一张地图，看到的是这份文件自己写的东西：它自己的小节标题、自己的顺序、自己的话。`Destination`、`Decisions so far`、`Not yet specified` 不是我们起的名字，是这份 map.md 里写着的；第一个 `##` 之前那段开场白照样显示，没有被塞进哪个小节。没有另外生成一份「地图结论摘要」。

文件里自己写成链接的地方，一处一处对着这个工作目录核过：指到本地票据的能打开那张票，指到工作目录里的文件的用现成的查看器读（只读，看完能回到原来那张票），指到的东西不在就写「打不开」，站外地址原样列出、不替你打开。没有一条是从措辞或者相近标题猜出来的——只有源文件自己写成 Markdown 链接的才会出现在这里。

从票据的结论进讨论、再从讨论回到来源，两边都是真的：讨论是这张票下真开的那段 Pi 会话，来回走一趟没发消息、没动活动叶子。

一张地图的票全部关闭时，旁边出现一条可关闭的小提示，问的是「还有未澄清的问题吗？通往目的地的路是否已经清楚？」——它问，不宣布。它不抢焦点，「查看地图」只是把这张地图打开来读。关掉之后刷新和重启都不再弹，要看可以从地图面板里再打开。

## 实现摘要

- 一个纯函数模块（[lib/waygoal-map.ts](../../apps/web/lib/waygoal-map.ts)）：`mapSections()` 按文件自己的 `##` 切分并原样保留正文，`mapLead()` 交出第一个 `##` 之前那段，`sourceLinks()` 只认 Markdown 链接。三者都不总结、不重排、不改名。
- 链接落地在 [lib/waygoal-tickets.ts](../../apps/web/lib/waygoal-tickets.ts) 的 `referencesFor()`：相对于写下它的那份文件解析，指到这个工作目录里任何一张票据的是 `ticket`（哪张地图的都算，地图之间本来就会互相指），指到目录里存在的文件是 `file`，越出工作目录或者根本不在就是 `missing`，带协议的是 `external`。「在不在」这一问只走 `safePath()` 一个入口——那是这个仓库里读文件的安全边界，符号链接绕出去也照样答「不在」。扫描结果因此多带一个 `cwd`：判断依据得跟着结论走。
- 「全部关闭」的判断在 [lib/waygoal-store.ts](../../apps/web/lib/waygoal-store.ts) 的 `mapCheck()`：问的是这张地图完整的票集合，不是叶子也不是当前视野；地图或票据显示的是上次读到的内容、有文件读不到、有同号多份、或者有哪张票写着一条读不清的依赖，都算「这个集合还不知道」，什么都不宣布。空地图没有「全部关闭」这回事。取消的票算进「时机」，但取消了几张会照实说出来。
- 关掉提示记在画布记录的 `mapCheckDismissed` 里（`{ 地图路径: true }`），和位置、来源、票据关联同住一份文件，所以刷新和宿主重启都不再弹；从地图面板里的「重新显示检查提示」把它设回 `false`。
- 提示文案照 [docs/design/canvas-navigation-and-states.md](../design/canvas-navigation-and-states.md) 里已确认的那两句写死，不读聊天、不调用模型、不调用 skill。「/to-spec」只在条件句里出现。
- 产物用的是应用本来就有的 `FileViewer`（[components/FileViewer.tsx](../../apps/web/components/FileViewer.tsx)），只读模式，没有新增任何产物编辑器，也没有新增通用知识图谱。文件读取走 `/api/files`，允许范围就是打开这个工作目录时已经放行的那一个。

## 有意的偏离

- 已确认文案写的是「这张地图的**决策票**都已关闭」，而这里的判断是「这张地图的**每一张**票都已关闭」——比字面更严，绝不会在还有执行票开着的时候说话。本地 tracker 的这套布局没有区分决策票和执行票的字段，所以现在按全部票来算；等来源真的分得出类型，再收窄到决策票。
- 「取消了 N 张」是在已确认的两句之外加的第三句。加它是因为验收明写「取消和移出范围不计作成功结论」，光靠那两句说不出这件事。要不要留，请用户定。

- 「关掉的提示可以重新查看」这一条，设计文档说的入口是缩略图旁边的小问号；这里做在地图面板里（打开地图 → 「重新显示检查提示」）。同一个地方既看地图又管这条提示，不必为它单开一个全局入口。要不要收进那个小问号，请用户定。
- 提示挂在地图卡片右边，跟着卡片走。屏幕很窄时它可能落在视野外，得先把地图卡片挪进来——现在没有为它做窄屏的另一种摆法。
- 票据正文里的链接和地图里的链接用同一套判定。也就是说票据 `## Answer` 里写的链接会出现在「来源指向」里，这正是「从结论回看产物」要的；但票据 `## Question` 里顺手写的链接也一样会出现，两者没有分开。
- 站外地址只列不打开：不发请求，也没做成 `<a>`。要不要允许在浏览器里打开，请用户定。
- 验收里的「会话关联」没有做成一种引用：本地 tracker 的这套布局里没有「把某段会话写成链接」的写法，所以从票据进讨论走的还是票 #8 那条路（票据下面列着它自己的讨论）。真要让来源文件写出一段会话，得先在 tracker 那边定个写法。

## 实测发现

- 一份被读到过、后来又被删掉的票据文件，会一直以「上次读到的样子」留在这张地图的票集合里（票 #7 定的行为）。所以删掉一张票之后，这张地图的检查提示就再也不会出现了——这不是这次的 bug，但它意味着「删票」和「把票标成取消」在这里是两件后果不同的事。端到端里用「文件暂时读不到、又读得回来」来验可逆的那一路。
- 判断「读全了没有」要同时看三处：地图自己是不是显示的上次内容、有没有文件读不到、有没有同号多份。少看一处，提示就会在集合还不清楚的时候冒出来。
- `mapSections()` 只按 `##` 切，第一个 `##` 之前的话不属于任何小节。要么把它单独交出来（`mapLead()`），要么就是显示时凭空丢掉一段——不能替来源安一个它没写过的标题。
- 引用要相对写下它的那份文件解析，不是相对地图目录：地图在 `.scratch/party/`，票据在 `.scratch/party/issues/`，同一个产物在两份文件里写出来的相对路径本来就不一样。
- 「这个去处在不在」不要自己写一遍 `startsWith("..")`：这个仓库已经有 `safePath()` 做这件事，它真的把路径解析出来，符号链接绕出工作目录也拦得住。判断存在与判断越界本来就是同一个问题。
- 一开始只在「这张地图自己的票据」里认票据链接，结果地图之间互相指的时候，对方的票据被当成普通文件用查看器打开了。票据的身份是「工作目录 + 来源路径」，认的范围就该是整个工作目录。

# Pi × Wayfinder 本地画布试跑

日期：2026-09-08。运行地址：`http://127.0.0.1:30142/beacon`。

> 这个原型入口（后来的 `/beacon/tickets`）已于 2026-09-11 删除，它的两件事都已在会话画布上（票 #7、#8）。下文是当时的记录，代码见 git 历史。

## 结论

可以用很薄的一层接入实现「票据节点 → 真实 Pi 会话 → Agent 更新票据 → 地图变化」，不需要导入仓库，也不需要另建任务执行引擎。界面复用 pi-web 的 ChatWindow、文件预览、会话管理和事件流；新增画布、本地 tracker 读取器、节点/会话关联文件与观察地图变化的 Pi extension。

## 真实模型证据

使用 `openai-codex/gpt-5.6-luna`。示例为事先写入的虚构放映会地图，初始含三张票据；不是模型从零生成的地图，也不是用户确认过的方案。

- 「希望朋友带走什么感受？」：Pi 调用了 Wayfinder，读取 grilling / domain-modeling 和 tracker 文档，将票据从 open 改为 claimed，向人提问后停止。没有提供模拟的人类答案。会话 `01a081c8-9d38-768e-896d-f9a195f8d66d`。
- 「这部短片适合怎样的开场？」：父会话 `01a081c9-4bcf-768e-896d-f9a32950518d` 调用 pi-web 内置 `Agent` 工具。研究子会话 `01a081c9-a4a6-768e-896d-f9a5a0979988` 使用同一 Luna 模型，查阅指定官方来源、写入 `playground/research/film.md`，父会话回写 Answer、resolved 和地图索引。
- Agent 自己新增了「看完之后怎样自然地开始交流？」；画布从三个节点变为四个。这个新问题和原有 prototype 节点都仍依赖尚未回答的感受问题，所以保持阻塞。
- Pi 会话文件中记录了 `beacon:map-changed` 自定义条目，来自 extension 对地图变化的观察。浏览器同时有定时刷新兜底。
- 三个实际模型会话的 assistant message model 字段均为 `gpt-5.6-luna`。检查后全局默认仍为 `openai-codex/gpt-5.6-sol`。

## 实测发现与修正

研究父 Agent 初次给新票复用了已有的 `03` 编号，还在当前会话问起新 HITL 票。没有把它当成成功：发送了结构修正指令，Agent 将新文件改为 `04-afterfilm.md`，补齐对 `01` 的依赖并清理地图中已经开票的“雾”。没有替用户回答新问题。

接入 extension 现在提示：创建前扫描全部编号并取最大值加一；当前票结束后让人到地图选择新节点。读取器遇到重复编号会显示提示，且不会凭含糊的依赖自动解锁。提示约束仍依赖模型遵守，尚不是原子化的建票 API。这是下一轮值得观察的可靠性问题。

## 验证范围

- TypeScript 全项目检查与改动文件 ESLint 检查通过。
- 十项相关测试通过：地图解析、作用域内依赖、缺失/重复编号不解锁、真实结论解锁、绑定持久化、目录边界、只在实际票据变化时发事件，以及上游模型偏好与子代理设置测试。

- HITL 的回答、确认和完整 prototype 反馈循环留给人试用；没有宣称这部分已验证。空目录起图入口已实现，但本次真实模型验证从预置地图开始。

## 暂定边界

本次只实现本地 Markdown 读取，没有 GitHub adapter。工作目录可以是普通文件夹。SDK 会话、模型、工具和登录复用 Pi，画布只保存关联和位置；不接管用户仓库或交付流程。固定的默认分层布局、重命名关联迁移和自动继续策略尚未产品化。

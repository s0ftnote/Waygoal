# 手动分组和关联想法（票 #6）试跑

日期：2026-09-10。入口：`http://127.0.0.1:30142/waygoal`（`npm run dev`）。票据：[#6](https://github.com/s0ftnote/Waygoal/issues/6)，父 Spec [#1](https://github.com/s0ftnote/Waygoal/issues/1)，前置 [#2](https://github.com/s0ftnote/Waygoal/issues/2)。

## 结论

按住 ⌘/Ctrl 点卡片是「挑」不是「打开」：面板不开，什么都不发。挑好之后起个名字就是一个分组——画布上出现一圈框和组名，里面还是原来那几张卡片，各自还是各自的 Pi 会话，谁也没多知道谁的内容。收起，它变成一张写着组名的卡片，成员从画布上让开；展开，同样几张卡片回到原来的位置。挑两张卡片、写一句说明，就是一条手动关联：画成实线、两端各一个点，和分叉的虚线、票据的依赖各是各的。连和删都只改画布记录，Pi 历史、活动叶子和票据文件一个字没动。改了会话标题，分组成员和关联说明都还认得它——认的是会话身份，不是它现在叫什么。停掉宿主再起来，组名、成员、布局和说明都在。

## 实现摘要

- 画布记录多了两样：`groups`（`{ id, name, members, collapsed }`）和 `links`（`{ id, from, to, note }`），跟位置、来源、票据关联同住一个文件（[lib/waygoal/store.ts](../../apps/web/lib/waygoal/store.ts)）。两样都是用户自己写下的，没有一处是推断出来的。
- 成员和关联端点用的是卡片自己的身份：会话是会话 id，票据是它在这个工作目录里的来源路径。标题只是显示，所以改名不动关系。
- 一张卡片同时只属于一个分组：放进新分组就从旧的里出来，旧分组空了就没了。规则写在 `applyCanvasPatch` 里，浏览器之外也测得到。
- 同两张卡片之间只留一条手动关联：再连一次是改那句说明，不是叠出第二条线。
- 位置只有一处来源（`record.nodes`）：分组收起时用的那张卡片也在里面，所以拖动、`回到全景`、缩略图和查找共用同一套算式。建分组时它先落在成员们的左上角。
- 收起的分组代表它的成员：成员卡片不画，分叉线和票据关联线也跟着安静下来。查找仍然按会话自己的标题找得到它，跳过去落在那张分组卡片上——画不出来的卡片不该变成一个能被送过去的地方。
- 手动关联是例外：一端在收起的分组里，线就画到那张分组卡片上。说明挂在线上，那个 `×` 是删掉这条关联的唯一入口，收起不能把它藏掉。两端都在同一个收起的分组里才没什么可画。
- 三种关系画得不一样，因为它们本来就不是一回事：分叉的线来自 Pi 的历史，票据依赖来自票据正文的 `Blocked by:`，手动关联来自用户自己这么说。手动关联是实线、两端各一个点（不声称方向），说明就挂在线上，`×` 就地删掉。
- 挑卡片、起名、连线都收在一个地方（[components/waygoal/Arrange.tsx](../../apps/web/components/waygoal/Arrange.tsx)）：没挑卡片时它不占地方，只在工具栏留一句怎么挑的提示。

- 按住 ⌘/Ctrl 点卡片只是挑：不开面板，不发消息。
- 起个名字就建好分组，成员正是挑中的那几张；没有新会话，没有一次模型请求。
- 画布上看得见组名，成员还是各自的卡片；每个成员仍是自己的会话文件，里面既没有组名也没有别的成员。
- 收起之后是一张写着组名的卡片，成员从画布上让开，但一段会话也没少。
- 收起状态下，成员仍按自己的标题被查找到，跳过去落在那张分组卡片上。
- 展开之后，还是那几张卡片，位置一模一样。
- 一条手动关联连在挑中的两张卡片之间，带着用户写的那句说明，说明就画在线上。
- 手动关联画成自己的一种线，不是分叉那条，也不是依赖那条。
- 一端在收起的分组里的关联，线画到那张分组卡片上，说明照看得见，也照删得掉，而且只删掉这一条。
- 连线没发任何消息、没挪动活动叶子、没改票据文件；被挡住的那张票据的真实依赖照旧。
- 改了会话标题，分组成员和关联说明都不受影响。
- 停掉宿主再起来：组名、成员、布局和那句说明都还在，也没重发任何命令。
- 删掉关联只少一条线；解散分组只少一个分组，里面的会话原样都在（连改过的标题也在）。
- 无页面脚本或控制台错误。

## 有意的偏离

- **一张卡片同时只属于一个分组**：验收只说「选择若干节点创建并命名分组」，没说不能重叠。这里选了不重叠：把一张卡片放进新分组，它就从旧的里出来；旧分组被搬空了就没了。理由是收起——一张卡片同时属于两个分组，收起其中一个，另一个的框就少了一块，界面说不清它在哪。代价是建新分组可能悄悄让一个旧组名消失。
- **同两张卡片之间只留一条关联**：再连一次是改那句说明，旧的那句直接被换掉，没有提示。验收只说说明是可选的，没说一对卡片只能有一条。这里选了一条，是为了不让重复点击叠出看不出区别的线。
- **分组不能改名**：验收要的是「创建并命名」，名字在建的时候写，没写名字就建不了。改名要再加一处输入框和一条 patch 字段，这张票没做；不合适就解散重建。
- **分组是一张画布内的事**：成员来自同一张画布，收起的分组也只出现在这张画布上。跨画布的分组要先回答「一段会话属于哪张画布」，那是票 #4 立下的规矩，不在这里翻。
- **手动关联不声称方向**：记录里有 `from` 和 `to`，画出来两端一样。用户说的是「这两件事有关系」，箭头会替他多说一句。

## 本票没有做的

- 成员或关联端点指向的会话文件被删了时，记录照旧留着，但画布上不画，也没有一处说「它不在了」。票 #8 在票据的讨论上是照实说的，这里还没有对应的说法。收起的分组不算这一类：那种情况线照画，只是画到分组卡片上。
- 分组不能嵌套，也不能拖着整个分组一起挪：框是跟着成员位置算出来的，挪成员框就跟着变。
- 挑卡片只有鼠标加修饰键这一种方式，键盘还没有对应操作。

## 实测发现

- 分组一收起，`回到全景`、缩略图和查找就会指向画不出来的卡片——和票 #8 里「回到全景没把票据卡片算进去」是同一类错：只要有一种卡片不进那份「画布上有什么」的清单，这三处就一起错。现在收起的分组代表它的成员进这份清单，成员按自己的标题仍找得到。
- 分组框如果自己接鼠标，里面的卡片就点不动也拖不动了。框整体不接指针，只有它的抬头接——这是这次唯一一处需要 `pointer-events` 的地方。
- 真实分叉的线本来就是虚线，所以手动关联不能也用虚线来「表示不确定」：现在它是实线、更粗、两端各一个点，一眼看得出是另一回事。
- 宿主重启的那几秒里，还开着的页面必然连不上，控制台会记下几条 `ERR_CONNECTION_REFUSED`。这是重启本身，不是页面的问题，所以只在这个窗口里不收集；窗口之外照收。
- 分组卡片的位置分配一开始写在「记录写盘」之后，等于白分配一次：成员都还没位置的分组每次读都重新算一个，而且这块地方在记录里仍然算空的，票据会被摆到它头上。所有分配位置的地方都必须在那一次写盘之前。
- 解散分组只删了分组，没把它那张卡片占的位置从记录里删掉——那块地方就一直被算作占用。删掉一样东西，要把它占的都还回去。
- 窄屏下画布连线整体不显示（`.waygoal-link { display: none }`），但手动关联的说明是另一个 HTML 元素，会留在画上飘着。线和挂在线上的东西得一起收。
- 端到端跑的时候改源码，Next 会一遍遍重编译，那次跑就废了：跑之前先把改动落定。

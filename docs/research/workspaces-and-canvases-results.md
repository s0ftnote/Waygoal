# 切换工作目录与一个工作区里的多张画布（票 #4）试跑

日期：2026-09-10。入口：`http://127.0.0.1:30142/beacon`（`npm run dev`）。票据：[#4](https://github.com/s0ftnote/Waygoal/issues/4)，父 Spec [#1](https://github.com/s0ftnote/Waygoal/issues/1)，前置 [#2](https://github.com/s0ftnote/Waygoal/issues/2)。

## 结论

一个工作目录一打开就有一张画布，不用先建。「新建画布」和「换一个目录」是抬头上两个分开的按钮：都只改现在看的是哪一块板子，不建票、不调用 skill、不发消息，也不启动会话。新建的画布上没有会话——已有的会话留在原来那张上，不会被搬过来，也不会同时出现在两张画布上；本地票据是这个工作目录的文件，每张画布都读得到，各自摆各自的位置。在哪张画布上开始聊，这段会话就属于哪张画布。画布的身份是它自己的 id，跟名字无关：两张都叫「选片」也还是两块板子。工作目录的身份是路径而不是文件夹名，两个都叫「放映会」的目录各有各的画布、布局和会话登记。切换目录只是换一个看的地方，不把新目录套到已有 Pi 会话上。刷新回到刚才那张画布，宿主重启后不带任何参数打开也回到上次的目录和画布；上次那个目录被移走了就把它的路径说出来，不悄悄换成别的目录顶上。输入一个不存在的路径同样照实说，并且把原来的画布留在屏幕上。

## 实现摘要

- 工作区记录是新的一份：`<agentDir>/waygoal/workspaces/<id>/workspace.json`，记着这个目录有哪几张画布、上次停在哪张、每段会话属于哪张（[lib/waygoal-workspaces.ts](../../prototypes/pi-web/lib/waygoal-workspaces.ts)）。画布布局仍是一张画布一份记录：第一张沿用原来的 `canvas.json`，后建的是 `canvas-<画布 id>.json`，所以票 #2 起写下的记录不用迁移。
- 读写的对象从「工作目录 + agentDir」换成一个 `WaygoalScope`（工作目录、画布、agentDir），`readCanvasRecord` / `applyCanvasPatch` / `buildSnapshot` / `buildTicketSnapshot` 都按它来（[lib/waygoal-store.ts](../../prototypes/pi-web/lib/waygoal-store.ts)）。工作目录的身份计算搬到 [lib/waygoal-paths.ts](../../prototypes/pi-web/lib/waygoal-paths.ts)，让工作区记录和画布记录都能用而不互相 import。
- 会话归属只写在工作区记录里，一段会话只能落在一张画布上。没人登记过的会话由第一张画布收下，而且只有第一张会收：这样票 #2 之前就在的会话留在原处，新建的画布上没有会话。从某张画布开始的会话（含分叉）在建立的当下就登记到这张画布（patch 的 `registerSession`）。读取顺手认领这件事写在名字里：`claimSessionsOn` 会写记录，不是一个纯查询。
- `recent.json` 记开过的工作目录，最近的在前。不带 `cwd` 打开时回到上次那个；那个目录不在了就报出它的路径，`resolveWorkspaceCwd` 不再退回样例目录顶上。开过的目录列表里，已经不在的那些照样列着并标注「这个目录不在了」，不能点，也不悄悄从列表里消失。
- 「新建画布」建完就把用户带过去——那正是刚才那一下要的。记录这一层不这样：`addCanvas` 不改这个目录停在哪张画布，换过去是界面另做的一步。
- 抬头换成 [components/WaygoalWorkspaceBar.tsx](../../prototypes/pi-web/components/WaygoalWorkspaceBar.tsx)：工作目录、开过的目录、这个目录的画布、新建画布。切换目录先读一次再切，读不通就只报错，屏幕上的画布不动。
- 画布和工作目录都写进地址栏（`?cwd=&canvas=`），刷新回到同一张；换画布时把面板上的东西一并放下，不让上一张的聊天盖在下一张上。

## 验证

单元测试：[lib/waygoal-workspaces.test.mjs](../../prototypes/pi-web/lib/waygoal-workspaces.test.mjs) 6 项（一个目录一开始就有一张画布且只有一张、同名的两张画布是两块板子、一段会话只在一张画布上而没人登记的落在第一张、切换记得住而这个目录没有的画布 id 被拒绝、同名的两个目录各记各的、上次开的目录能回去而移走了的照实说）；[lib/waygoal-store.test.mjs](../../prototypes/pi-web/lib/waygoal-store.test.mjs) 追加 1 项（同一目录的两张画布各有各的视野、各有各的记录文件、各有各的会话），并把已有的约 90 处调用改成按 `WaygoalScope` 读写。

浏览器验证（`npm run test:waygoal-workspaces`，[e2e/waygoal-workspaces.mjs](../../prototypes/pi-web/e2e/waygoal-workspaces.mjs)）：隔离的 `PI_CODING_AGENT_DIR`、独立 Next 宿主、本机假模型，两个末级名字都叫「放映会」的临时工作目录。20 项检查全部通过：

- 一个工作目录打开就是一张「主画布」，抬头显示的就是要打开的那个目录。
- 在这张画布上开始的聊天出现在这张画布上。
- 新建画布不发一次消息、不建一个会话文件；新画布上没有会话，原来那段聊天还在原来那张上；这个工作目录自己的地图和票据在新画布上照样看得到，位置由这张画布自己记。
- 在第二张画布上开始的聊天只在第二张上；回到第一张看到的是第一张的那段，看不到第二张的。
- 只缩放第二张画布，第一张的视野不变；两张画布各有各的记录文件。
- 刷新回到刚才那张画布，而不是回到第一张。
- 换到另一个同名目录：它自己只有一张空画布；换目录不发消息，也没有把留在原目录的会话改到新目录。
- 输入一个不存在的路径：把这个路径说出来，屏幕上的画布还是原来那个。
- 停掉并重启宿主，再不带任何参数打开：回到上次的目录和上次那张画布，两段聊天各自还在自己的画布上。
- 上次开的目录被移走之后，不带参数打开会报出它的路径，而不是换一个目录顶上。
- 除了那次故意打不开的目录之外，没有别的失败请求，也没有页面或控制台错误。

证据：截图 `prototype-evidence/workspaces/01-second-canvas.png`、`02-other-workspace.png`、`03-after-restart.png`，检查记录 `checks.json`。同时通过全项目 TypeScript 检查和 `components`、`lib`、`app`、`e2e` 的 ESLint。

## 有意的偏离

- **本地票据不按画布分**：票据是工作目录里的文件，所以同一个目录的每张画布都读得到同一批票据，各自记各自的位置；按画布隔离的是会话、布局和最近位置。验收里写的是「布局、最近位置和新增会话登记按范围隔离」，票据本身不在这三样里。要不要让不同主题的画布只看到自己的那几张票据，请用户定。
- **换目录是输入路径**：用户输入的目录会进入 `/api/files` 的允许根列表（`allowFileRoot`），也就是说界面上多了一个把任意目录加进这个列表的入口——在这之前只能手改地址栏。这是「切换工作目录」本身要求的，但它确实扩大了这个原型的文件访问面。

## 本票没有做的

- 把已有的会话搬到另一张画布：现在一段会话属于哪张画布只在它开始的时候定下来，之后没有搬动的入口。票据要求的是「不引入跨画布共享同一会话」，搬动是另一件事。
- 查找（票 [#5](https://github.com/s0ftnote/Waygoal/issues/5)）仍然只找屏幕上这张画布的卡片。另一张画布上的讨论要先切过去才找得到；跨画布查找和跨工作目录查找一样，留着没做。
- 画布改名、删画布：票据没有要求，也就没有加。
- 目录选择器仍是输入路径加一份开过的目录列表，没有调用系统的目录选择框。

## 实测发现

- 「上次停在哪张画布」是读的时候写下的：带 `?canvas=` 读一次，就等于说现在停在这张。浏览器轮询正好是这个意思，但测试里顺手读一下另一张画布也会改掉它——检查某张画布上有什么，就得把画布名写进这次读取里，不能省。
- 换目录原本是先把屏幕清空再去读，路径打错就只剩一个「…」。改成先读通再切：读不通就只多一行错误，画布还是原来那张。
- 读画布失败的提示原本会被 2.5 秒后的下一次轮询抹掉，用户自己那次操作的错误也一起没了。现在只有读画布自己报的错会被下一次读取收回。
- 一段会话「没人登记过就归第一张画布」这条，只能让第一张画布来收。让每张画布都收，切过去一次就把整个目录的会话都拖了过去。
- 页面会把落到的目录和画布写回地址栏，这在 Playwright 眼里也是一次跳转：从一个已经打开的标签页 `goto` 到不带参数的 `/beacon` 会被它自己打断，得另开一个标签页——而且要先开新的再关旧的，反过来会把整个 context 一起带走。
- 视野是延迟 500 毫秒才存的，换画布时原本会连同定时器一起丢掉。现在离开一张画布之前先把还没存的视野存下来。
- 「新画布是空的」这句话只有在工作目录里没有票据时才成立。e2e 原本正好用的是没有票据的目录，这句话就一直没被验到；现在目录里放了一张地图和一张票据，检查改成分开数会话卡片和票据卡片。

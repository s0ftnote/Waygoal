# 从票据开始、分叉和继续讨论（票 #8）试跑

日期：2026-09-10。入口：`http://127.0.0.1:30142/beacon`（`npm run dev`）。票据：[#8](https://github.com/s0ftnote/Waygoal/issues/8)，父 Spec [#1](https://github.com/s0ftnote/Waygoal/issues/1)，前置 [#3](https://github.com/s0ftnote/Waygoal/issues/3)、[#7](https://github.com/s0ftnote/Waygoal/issues/7)。

## 结论

一张还没有讨论的票据，点「还没有讨论，开始聊」就是打开一个空的输入框：不建立会话，不发消息，不跑 skill。改了字再关掉面板、再点一次，回到的还是同一份草稿，而不是又多出一段讨论。发送才是真正开始：那一刻建立真实 Pi 会话，并挂到这张票据下。一张票据可以带好几段讨论；从某段讨论里真正分叉出去的那段，仍然算这张票据的讨论，票据不会被复制，也不会因此多一条依赖。票据记着上次在聊哪一段，也记着它的讨论是摊开还是收起；收起只是不在画布上摊开，票据里照样接着聊。被依赖挡住的票据和已经 resolved 的票据都还能讨论，聊天本身不改它们的状态。关联指到的会话不在了，就照实说「打不开」，不按标题换一段顶上。

## 实现摘要

- 关联存在已有的画布记录里（`<agentDir>/waygoal/workspaces/<id>/canvas.json`）：`ticketSessions`（会话 → 票据来源路径）、`ticketExpanded`（票据 → 摊开还是收起）、`ticketLast`（票据 → 上次在聊的会话与位置）。三者都按工作目录隔离，替掉了票据原型里「一票只绑一段会话」的限制。
- 分叉沿用票据：`applyCanvasPatch` 记下 `origin` 的同时，把来源会话所属的票据带给新会话（[lib/waygoal-store.ts](../../apps/web/lib/waygoal-store.ts)）。规则只写在这一处，浏览器之外也测得到。
- 开始入口复用宿主已有的「新建会话不发送」和草稿能力：草稿键是「票据来源路径 + 工作目录」，稳定不随点击变化。宿主会在新建会话的输入框卸载时清掉它的草稿，所以未发送的票据草稿在没有输入框拿着它的时候寄存在票据自己的键下，下次打开再交回来（`liveTicketDraft` / `parkedTicketDraft`，[components/WaygoalCanvas.tsx](../../apps/web/components/WaygoalCanvas.tsx)）。交回要在输入框渲染之前做——它是在渲染期读草稿的，放进 effect 就晚了一帧。
- 票据卡片下摊开的是这张票据的讨论：一枚「N 段讨论 · 收起／展开」，每段讨论一枚，最后一枚是「另开一段讨论」。票据仍然平铺，没有把会话套进大容器；没挂票据的会话照旧是独立卡片。收起时这些 chip 和票据到会话的关联线一起安静下来，关联本身不变。
- 画布位置分配把票据卡片算作更高的一块（`TICKET_CARD_HEIGHT`，[lib/waygoal-types.ts](../../apps/web/lib/waygoal-types.ts)）：讨论 chip 挂在票据下面，新会话不该被摆在它们头上。「回到全景」同样把票据卡片和它摊开的讨论算进去。
- 完整视图里列出这张票据下的讨论（[components/WaygoalTicketPanel.tsx](../../apps/web/components/WaygoalTicketPanel.tsx)）：上次在聊哪一段、哪一段正在运行、哪一段是从这张票据的另一段分出来的、哪一段已经打不开。收起之后从这里接着聊，不用先重新摊开。
- 操作提示是写死的一句话，句子里就写着它的出处（「Waygoal 对这个入口的说明，不是从你的对话里总结的」），可关可再开（记在 `localStorage`）。它不读聊天内容、不调用模型、不注入聊天上下文；关掉之后开始、分叉、继续都照常。
- 回看和在聊是分开的（沿用票 [#3](https://github.com/s0ftnote/Waygoal/issues/3) 立下的区分）：只读回看只移动画布层面的「正在看」，不改票据记着的「上次在聊的那一段」；在某条路径上发送才改，而且连那条路径一起记下。
- Pi 有时只说得出分叉来自哪段会话、说不出来自哪条消息。这种分叉画布会直接写下它属于哪张票据，不靠来源记录带过去——否则它会悄悄掉出票据。

## 验证

单元测试：[lib/waygoal-store.test.mjs](../../apps/web/lib/waygoal-store.test.mjs) 追加 6 项（票据带着它的讨论并跨重启保留、从讨论分叉出去仍属同一张票据、会话不在了显示为打不开而不静默替换、记住上次在聊的一段与摊开／收起、跨工作目录或空票据路径的关联被拒、会话卡片不会被摆在票据的讨论上；只说得出来源会话的分叉也留在同一张票据下），并把已有的位置分配那项改成按真实高度断言。

浏览器验证（`npm run test:waygoal-ticket-talks`，[e2e/waygoal-ticket-talks.mjs](../../apps/web/e2e/waygoal-ticket-talks.mjs)）：隔离的 `PI_CODING_AGENT_DIR`、独立 Next 宿主、本机假模型，工作目录里是真实布局的地图与票据。26 项检查全部通过：

- 没有讨论的票据照实说「还没有讨论」，不看着像已经聊过。
- 从票据开始聊只打开输入框：没有会话文件，也没有一次模型请求。
- 关掉面板再点一次，回到的是同一份没发送的草稿，不是第二段讨论。
- 发送之后这段讨论挂在这张票据下；被依赖挡住的票据照样能聊，状态不变。
- 画布上票据下面出现这段讨论，并画出关联线。
- 从讨论里真正分叉出去的那段仍属同一张票据，票据没有因此多一条依赖，分叉是独立的 Pi 会话文件；同一段讨论分出两条分支，两条都还是这张票据的讨论，也是两个独立的会话文件。
- 从分支回看来源那条消息是只读的：没有一次模型请求，票据记着的「上次在聊的那一段」也没被回看带走。
- 讨论正在运行时收起票据、关掉面板，都不打断它：那次回答照样落进这段会话。
- 一张票据带四段讨论，票据记着上次在聊的是哪一段。
- 收起把讨论和关联线一起从画布上收走；从票据里仍然能打开某一段接着聊，打开本身不发送。
- 已经 resolved 的票据也能补充讨论，聊完还是 resolved。
- 停止并重启宿主后，讨论、收起状态和上次在聊的位置都还在，且没有重发任何命令。
- 删掉某段讨论的会话文件后，它显示为「打不开」，画布没有替换成另一段。
- 无页面脚本或控制台错误。

## 需要用户确认的

前两条是这张票据里明确要求由用户判断的，第三条是一处有意的偏离：

- **有界真实试跑**：验收里写的是用 `gpt-5.6-luna` 做一次有界真实试跑。上面的浏览器验证用的是本机假模型（不涉及任何登录与密钥），真实试跑要用用户自己的 Pi 登录跑一次。
- **聚会策划样例走查**：验收要求拿一个聚会策划的例子，从票据开始、分叉、深入再返回走一遍，然后请用户确认「能不能认清自己在哪、下一步往哪走」。e2e 用的正是一个聚会策划样例（放映会：想让朋友带走什么感受 / 开场怎么说 / 吃的准备什么），截图已留下，但这条要的是用户的判断，测试通过和模型试跑都不能代替。
- **AC2 的「仅准备精简 Wayfinder 调用和实际来源引用」没有做**：开始一段讨论现在就是打开一个空草稿，正文完全由用户自己写。理由有两条——README 里写明这个原型「没有固定的 Wayfinder 根入口或自动路由」，替用户塞一段 Wayfinder 调用会推翻它；票 [#7](https://github.com/s0ftnote/Waygoal/issues/7) 立下的是「程序自己读来源文件，Agent 不用再抄一份正文」，把票据正文预填进聊天框正是再抄一份。票据来源在面板抬头和完整视图里都看得到。这条要不要按原文补上，请用户定。

配套的一个体验问题，留给同一次走查：一段讨论现在同时出现两次——票据下的一枚 chip，和画布上它自己的会话卡片，中间由一条虚线关联。这样是「票下看得见、卡片仍可自由摆放」，还是重复得多余，需要用户看过截图后定。

## 本票没有做的

- 依赖变动之后下游票据解锁的提示留给票 [#9](https://github.com/s0ftnote/Waygoal/issues/9)；本票只保证聊天不改票据状态。
- 关联只在这一个工作目录内：指向别的工作目录的会话的关联会被拒绝，而不是跨画布显示。

## 实测发现

- `PATCH /api/waygoal` 是按字段挑着转发的，新加的三个字段没写进去就被静默丢掉：store 的单元测试全绿，界面上却什么都没挂上。字段白名单的代价是每加一个字段都要记得改两处。
- 宿主会在「新建会话」的输入框卸载时清掉它的草稿（`useAgentSession` 的卸载清理），所以稳定的草稿键本身不够——草稿得在没人拿着的时候寄存起来。而且交回必须早于渲染：输入框在 `useState` 初始化时读草稿，放进 effect 就晚了一帧，看到的是空的。
- 又是截图而不是断言暴露的两处：新会话被自动摆在票据的讨论 chip 上面（位置分配只按会话卡片的高度算），以及「回到全景」根本没把票据卡片算进去——点一下就把票据推出画面。两处都改成按真实高度计算。
- Pi 不在一段会话的第一条消息上提供分叉入口（没有可分的东西），所以分叉要从第二条消息起。
- 空票据上「收起」是没有意义的：现在没有讨论的票据只有一枚「还没有讨论，开始聊」，收起／展开只在真的有讨论时出现。
- 「上次在聊的那一段」原本被只读回看也写了一遍：翻一段历史，票据就改口说「上次在聊这段」。回看和在聊在票 #3 里就是分开的两件事，这里不能又合回去。
- 悬停才出现的每条消息操作在浏览器验证里很容易点错：上一次悬停留下的按钮还在，`.first()` 就会点到别的消息上。现在先把鼠标挪开、等按钮消失再悬停。
- 画布位置分配和「回到全景」原本各写各的票据高度算式，第一次就已经因此错位。现在只有一处 `ticketChipTop` / `ticketCardHeight`，摆放、全景和渲染共用。

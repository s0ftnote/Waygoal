# 远程原文也走同一票据入口（票 #10）试跑

日期：2026-09-10。入口：`http://127.0.0.1:30142/beacon`（`npm run dev`）。票据：[#10](https://github.com/s0ftnote/Waygoal/issues/10)，父 Spec [#1](https://github.com/s0ftnote/Waygoal/issues/1)，前置 [#7](https://github.com/s0ftnote/Waygoal/issues/7)。

## 结论

Agent 按平常的方式读完一张远程票据之后，交给画布的只有两样东西：这是哪个来源的第几号，以及它自己那份原始结果放在哪。正文是 Waygoal 自己去读的。Agent 不复述正文，也没有机会用改写稿冒充原文——交付入口根本没有正文这个参数。

来源上的操作成功，和画布同步成功，是两件事，记成两件事。前者是这次交付发生的原因，后者是这次交付回答的问题：读到了就是取得于某时某刻，没读到就是「未同步」，卡片照样在画布上，只是不显示任何冒充来源的内容；把结果重新写回工作目录，点「重新取得」就能再取一次，还是原来那张卡片。

提交票据时用过的那份本地正文文件，这里从不拿来当票据正文——正文只从来源自己的结果里读。平台把正文改写过（模板、编号、自动补充）也不影响：读到的就是平台改完之后的最终记录，因为读的是 `gh` 从平台取回的结果，不是提交前的那份草稿。

GitHub 和离线自定义样本走同一个入口，各自成一组，用的是本地票据那一整套快照和画布身份机制：同样的卡片、同样的位置、卡片下面同样能挂讨论。`10` 这个裸编号在 GitHub、在样本、在本地地图上同时存在时是三张票，互不认领；样本里那张写着「等 3 号」的票，等的是样本自己的 3 号，不会去认 GitHub 的 3 号。

看到的是取得那一刻的原文：正文一个字不改，取到的评论按取到的样子列出，没取评论的那次明说是「评论没取到」而不是「没有评论」，附件和链接只按地址列出、不下载也不代打开。来源上后来改了什么，要等下一次取得才知道——面板上就是这么写的，没有承诺实时同步。Web 侧不维护第二份正式正文，也不需要另配 OAuth。

## 实现摘要

- 一个纯函数模块（[lib/waygoal-remote.ts](../../prototypes/pi-web/lib/waygoal-remote.ts)）：`readRemoteResult(source, raw)` 按交付说的来源身份去读那份原始结果，读不出就明说未支持并写出该用哪条命令，绝不半读半猜；`supersedes()` 只认来源自己的时间——比已确认的旧、或者根本没有时间，都不覆盖；`remoteTicketPath()` 把来源身份编进卡片 id，所以同号跨来源天然不撞。
- 支持的格式写死两种：`gh issue view <编号> --json number,title,state,stateReason,body,url,updatedAt,comments` 的输出，和一份离线样本的 JSON。`gh` 的其它输出一律算未支持——「任意 Bash／gh 输出都能自动提取」这个前提没有被采纳。GitHub 的 `CLOSED` 分成 `COMPLETED`（做完了）和 `NOT_PLANNED`（不做了），落到本地 tracker 已经在用的 `resolved` / `cancelled` 两个词上，所以依赖结算不用为远程票另写一套。
- 交付和取得在 [lib/waygoal-remote-store.ts](../../prototypes/pi-web/lib/waygoal-remote-store.ts)：`deliverRemoteTicket()` 收到交付就立刻去读那份原始结果——趁引用还没失效；读到了记 `capturedAt` 和原文快照，读不到就只记 `deliveredAt` 加一条说明。原始结果必须落在工作目录里，读它走的是 `safePath()`，也就是这个仓库读文件的那一个安全边界。同一张票再交付只是覆盖同一条记录，不会多出一张卡。
- 交付入口是 extension 注册的工具 `waygoal_remote_ticket`（[lib/beacon-extension.ts](../../prototypes/pi-web/lib/beacon-extension.ts)）。选它是因为它是唯一稳定触发的通路：Pi 用校验过的参数来调，不用去猜 Agent 的散文，也不用改 Matt 的流程。提示只有一行 `promptSnippet`，没有加长系统提示。
- 远程来源在画布上就是一组票据视图（`remoteMapViews()`），和本地地图共用 `WaygoalTicketMapView`，所以位置、分组、手动关联、依赖连线、查找、票下讨论全都不用再写一遍。唯一的分别是 `remote: true`——来源镜像没有自己的 Destination，所以不出检查提示。
- 重新取得走 [app/api/waygoal/remote/route.ts](../../prototypes/pi-web/app/api/waygoal/remote/route.ts)：它只是再读一次 Agent 已经产出的那份结果，不连平台、不需要登录、也从不往来源写任何东西。

## 有意的偏离

- **AC1 的「真实 skill 调用」只做到了机制核实这一步。** 注册工具会不会被真实模型在真实 skill 流程里稳定调用，得跑一次真模型才知道；这次没有跑（同票 #8 的有界真实试跑一样，留给用户定）。已经核实到的是：工具注册在会话里生效、参数经 Pi 校验、handler 拿到的就是来源身份和引用，端到端的后半段（取得 → 快照 → 画布）由上面那 27 项覆盖。**这一条请用户确认要不要补一次真模型试跑。**
- **端到端测试里的交付调的是 `deliverRemoteTicket()`，不是让模型去调那个工具。** 让模型调工具就得跑真模型，而这套端到端是不联网、不跑真模型的。工具本身收什么、答什么，由单元测试那一项盖住。
- **支持的来源写死两种，且格式判定靠交付里声明的来源身份。** 声明 `github` 却给了一份不是 `--json` 的输出，答的是「未支持」，不去嗅探。这是有意的：嗅探格式就等于开始猜。
- **`origin` 是 Agent 说了算的一个名字**（GitHub 上就是 `owner/repo`）。程序只校验它是个普通名字、不能藏路径，不去核对它真的对应那个仓库。要不要拿结果里的 `url` 反查校验，请用户定。
- **来源自己的结果不带时间，就排不出先后。** 先后只在两边都有时间的时候才排：已确认的那份没带时间时，后来的结果不静默顶替它，写明「顺序不明，没有采用」，要换得先重新取得一次带时间的结果。反过来也是有意的——宁可多留着已确认的那一份，也不让一份不知先后的结果悄悄盖掉它。
- **原始结果必须落在工作目录里。** 换来的是读它可以复用 `safePath()` 这一个安全边界，代价是 Agent 得先把 `gh` 的输出写进工作目录（例如 `.scratch/remote/<编号>.json`）而不是留在别处。引用写相对路径时，相对的是那个工作目录，不是宿主进程自己所在的目录；工作目录经软链接打开时，和它的真实路径算同一个工作区。
- **来源镜像不出检查提示。** 一组来源票据全关闭时不提示「回去核对目的地」——它没有目的地。要不要给来源也来一条别的提示，请用户定。
- **没有做「来源那边改了」的主动发现。** 变更要靠 Agent 再交付一次；画布自己的 2.5 秒轮询只读本地记录，不去问平台。这是 AC5 明写的边界。

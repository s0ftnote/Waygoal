# 连续对话与生长画布 · 可丢弃原型

2026-09-15。设计问题：**右侧保持同一个完整对话与输入框，左侧随轮次生长；连续发送、回看、定位和明确分叉时，用户能否掌握当前路径？**

## 已确认的方向

用户认可轮次卡片和手动连线，要求移除“可回看”“一轮问答”等无用标签。随后明确纠正：右侧应保留 pi-web 的完整历史、持续输入与快捷节点导航；普通聊天不需要逐张选择卡片。只有明确的 tree 路径选择或分叉才改变继续路线。

Session 承载树，消息 entry 才有 parentId；卡片是对话的展示单元，不为每轮新建一个 session。原型使用一个内存会话树，每条用户和 Agent 消息都有真实对应的样例 parentId，卡片呈现一轮问答。

## 当前操作

- 在右侧输入框连续发送。每次发送在当前路径下添加消息、左侧生长卡片，右侧保留已有历史和同一个输入框。
- 点击左侧当前路径中的卡片，仅滚动右侧历史；右侧快捷节点导航和消息旁的定位入口同步定位左侧卡片。
- 点击其他路径的卡片，在画布内预览，右侧当前对话和未发送输入保持原样。预览布局是本轮待试用方案。
- 点击 Tree 选择路径，右侧才切换为所选路径的完整历史。切换前的未发送输入和引用分别保留。
- 从 Agent 回答明确分叉，之后仍在同一位置连续输入；修改用户消息并分叉时，以该消息的 parent 为起点，并把原文放进输入框。
- 使用“引用连线”，把已有卡片连到“下一轮”，随后仍在右侧发送。引用可选择整轮、回答、用户消息、完整路径或回答摘录。已有历史中的消息不重复加入。
- “仅作关联”只标记有关，再连同一对即可取消，不改变输入或当前路径。
- 连线点只在连线模式显示，卡片保留编号、问题和回答预览。具体消息操作在右侧悬停或键盘聚焦时显示，触屏保持可见。
- 底部四个演练：连续聊天、双向定位、分叉与返回、引用下一轮。切换演练会重置样例。

## 本机 Chrome 操作结果

未新增测试文件；使用真实浏览器交互和 DOM 检查验证：

- 从初始 4 张卡片连续发送 3 次后有 7 张卡片；右侧当前路径从 3 轮变为 6 轮。
- 发送前后的输入框、历史滚动容器和第一轮消息均为同一个 DOM 节点；发送后焦点仍在输入框。
- 在有未发送草稿时定位 01，当前路径仍在 07，草稿完整保留。右侧第一轮实际滚到历史容器顶部下方 16px。
- 预览另一条路径 04 时，右侧仍有原来的 6 轮历史，草稿未变。明确通过 Tree 切到 04 才展示 01 → 04；切回 07 后恢复原草稿。
- 从 02 分叉、连续发送两次，再通过 Tree 切回 03，恢复 01 → 02 → 03。
- 从 04 手动拖线到下一轮，连线成功且草稿保留；发送后引用线连接到实际新增卡片，右侧仍沿原路径继续。
- 1440px 桌面与 390px 窄屏已检查；页面无横向溢出，浏览器无脚本错误。窄屏将画布和对话上下排列。

## 边界与后续

当前仍是静态样例与模拟回复，没有接入真实 Pi、模型、工具、持久化、skills 或 tracker。右侧用原型模拟 pi-web 的持续聊天与快捷导航，不声称已复用生产组件。

前一版“每张卡片一个准备面板，再点下一张继续”的实现思路已撤回。下一轮生产接入应以现有 ChatWindow 的会话生命周期为底座，让卡片投影和双向定位订阅它；纯定位不重挂载聊天组件、不改变活动 leaf、不丢失草稿。跨分支预览、引用材料快照和历史压缩的真实接入仍待验证。

# 票据成功后通知 Web · 接入实验

日期：2026-09-09。验证问题：能否让 Pi Agent 继续按原 tracker 的方式操作工单，再调用一个统一通知工具，使 Web 无需分别登录、读取各 tracker 就能显示节点？

## 范围与运行

在 pi-web 目录执行 `node experiments/tracker-notify/run.mjs`。需要已配置的 Pi 登录、`openai-codex/gpt-5.6-luna` 模型，以及可读取公开 GitHub Issue 的本机 `gh`。运行会使用模型，覆盖本目录标记为 `PROTOTYPE-wipe-me` 的测试文件和实验输出；接收端监听 http://127.0.0.1:30143 ，完成调用后页面继续运行，Ctrl-C 停止。

当前项目 `s0ftnote/Waygoal` 查询时没有工单。本次用用户先前提供的参考项目 `agegr/pi-web` 中 Issue 786 的真实只读快照验证远程来源数据，没有创建、修改或关闭任何远程工单。自定义 tracker 只使用刻意采用另一种字段格式的虚构 JSON 样本，不代表已经接通某个真实第三方平台。

## 实际机制

`run.mjs` 通过内联 Pi extension 注册 `waygoal_publish_ticket`。Luna 使用 Pi 的 read/write 工具处理本地样例，再主动调用通知工具。通知工具发送 HTTP 请求到 `receiver.mjs`；后者不加载 GitHub SDK，不运行 gh，不读取 tracker 文件，不持有 tracker 凭据。它只接受统一的完整票据快照：

- `sourceKey`：来源中的唯一身份，更新时复用。
- `source`、`locator`：显示来源以及回到实际工单的引用。
- `title`、`body`、`status`、可选 `answer`：节点内容。
- 可选 `mapRef`、`blockers`：地图及依赖。省略 blockers 表示未核对，空数组才表示已知没有依赖。

通知工具生成事件 ID，先写本地待发送记录再提交。接收端用来源身份更新同一节点，用事件 ID 去重；一次模拟 503 后，工具使用同一事件重试。本实验保留删除记录，让来源删除与未完成区分开来。

## 实测发现与第二轮调整

第一轮原始资料保存在 `raw-attempt/`。HTTP 接收、更新和重试检查通过，但人工检查完整工具调用发现：Luna 抄写长的中文编码 URI 时弄错地图引用和依赖引用，部分错误被它随后修正，删除通知中仍留下错误依赖。原先断言没有覆盖所有关系字段，不能把请求成功当成关联正确。该轮报告已明确标为身份检查失败，保留原始调用。

第二轮让宿主保存完整引用，Agent 只选择 `local-01`、`local-map`、`github-786` 等短引用。extension 验证短引用并展开为完整身份后发送，Web 接收格式完全没变。增加了建票、修改及删除三个阶段的地图/依赖精确核对。

第二轮实际运行通过六项检查：本地真实文件与通知正文一致；重复事件不新增节点；503 后同一事件重试成功；GitHub/自定义快照由同一个接收端接收且保留未知依赖；地图和依赖引用在三个阶段准确；删除后保留身份并退出当前节点。最终显示三个当前节点和一条删除记录。全部 assistant 消息使用 `openai-codex/gpt-5.6-luna`。

本实验的引用表由驱动程序根据已知样例路径和实际 GitHub 读取结果构造；没有验证对任意 tracker 的创建回执自动提取身份。正式接入应把创建/读取成功得到的真实引用注册给宿主，这部分还需结合 Pi 的来源操作路径设计。

## 验证资料

运行结果以 `evidence.json` 的 `passed`、`checks` 和异常字段为准。`session.json` 保存实际模型及工具调用；`snapshot.json` 保存 Web 最后接收的状态；`outbox.json` 保存未确认通知。网页直接读取运行中的接收端状态，不是固定回放。

实验依次检查：本地建票及依赖通知、重复通知不新增节点、修改标题和状态不改变身份、首次通知失败后的重试、真实 GitHub 快照字段保留、自定义字段由 Agent 转换、得到明确删除回执后的节点删除标记。

## 不能从本实验推出的结论

- 不是一次完整 Wayfinder 流程：本次只加载通知 extension 和限定的实验指令，没有加载 Wayfinder、setup 或其他全局 skills。实际技能编排下是否仍可靠通知，需要单独验证。
- GitHub 只验证真实读取结果到 Web 的路径，没有验证 GitHub 建票成功后的自动通知。自定义来源只验证接收端不依赖固定平台，实际平台的操作仍需要 Agent 具备相应能力。
- `sourceKey` 在本地样例中使用文件 URI；重命名迁移未解决。事件不会自动携带 Pi 会话绑定；本实验只验证节点数据接收。
- 外部直接修改不会被接收端发现；实验中的删除由驱动程序执行并明确告知 Agent。
- 待发送文件有保留，但未实现进程重启后的自动恢复；接收端在内存中运行。多会话并发、乱序通知和旧快照覆盖也未实现。
- 通知内容来自 Agent，接收端不独立证明它与来源一致。本次驱动程序逐项比对真实文件和 GitHub 快照；正式接入需要考虑如何发现漏报、错报。

这份实验验证的是“已有来源操作能力 + 统一通知工具”的可行性，不是一个完整工单同步产品。原有无限画布和项目 tracker 配置均未修改。

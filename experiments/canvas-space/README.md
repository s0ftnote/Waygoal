# 会话空间 × 可选票据 · 交互原型

## 当前版本：B 改造（2026-09-10）

用户选择 B 的平铺画布，票据是上层工作单元，会话挂在票下或收进票里；不继续 A 的大容器与 C 的路径布局。当前页面只保留改造后的 B，旧 A/C URL 会归到 B。下方 2026-09-09 内容是历史实验记录，不再是当前页面操作指南。

运行命令仍为 `npm run prototype:canvas`，打开 [B 改造版](http://127.0.0.1:30145/canvas-space/index.html?variant=B)。

- 默认显示 #12 和其三段讨论、尚无会话的 #13，以及两段未挂票的独立会话。票据来自虚构夹具，页面不分析聊天或自动开票。
- 票据卡直接提供开始／继续讨论；点击标题可看原文和票下会话。已有讨论按明确记录的上次继续位置恢复，也可从票内选择其他会话。
- #13 开始讨论后才建立样例会话，输入框准备 `/skill:wayfinder #13`，发送前聊天消息数为零。这里的命令与编号是样例，不是对任意 tracker 的真实解析。
- 会话与分支可挂出在票下，也可收起，从票内继续；继续不会强制展开画布中的会话。分叉保留票据归属、来源消息及其之前的路径。
- 新开普通会话保持独立；上方可显式切换纯会话样例，该操作重置内存夹具。

本机 Chrome 已实际操作空票创建、发送、分叉、收起后继续、只读回看、解锁、新开独立会话及纯会话切换。确认空票命令尚未发送；#13 在阻塞时可开始讨论但保持等待；收起后会话节点不在画布上重复显示，仍能继续同一分支。390px 无页面横向溢出，浏览器未出现 pageerror。未新增测试文件。截图为 `b-revised-overview.png`、`b-revised-inside.png`、`b-revised-mobile.png`。

## 历史：三方案比较（2026-09-09）

2026-09-09。待回答的问题：**票据展开承载会话，还是票据与会话全部平铺，更容易让用户理解关系，并完成分叉、深入和返回？**

这是 UI 分支的可丢弃原型，不是生产接入。采用静态页面，与既有 `../return-to-thread/index.html` 相邻；当前 Beacon 页面固定以票据创建会话，其数据与入口限制不适合用来比较普通会话空间。这里不改动该页面或其真实会话操作。

## 运行与比较

在项目根目录运行：

```sh
npm run prototype:canvas
```

打开 [交互原型](http://127.0.0.1:30145/canvas-space/index.html?variant=A)。HTML 自包含，也可以直接打开本目录的 `index.html`。底部按钮或左右方向键切换方案，输入时不拦截方向键；URL 保留方案选择。其余状态仅在内存，刷新后重置。

- **A / 容器**：#12 的关联讨论收在一个可展开的区域里，其他会话独立摆放。
- **B / 平铺**：会话与票据各占一个位置，通过不同连线展示分叉、挂载、依赖。
- **C / 路径**：聚焦当前会话及其直接分支，通过来源路径返回；其他起点和票据放在下方。

相同样例与操作跨方案保留，拖动位置按方案分别保存于内存，便于比较。页面固定标明无模型连接；`ⓘ` 显示查看位置、继续位置、会话数、票据数、状态、来源、挂载与最新操作。没有自动生成标题、自动判断关系或流程路由。

## 体验路径

1. 点开“聚会想法”，从用户消息分出“电影”方向，添加一条样例消息。
2. 回看来源；底部继续位置应留在电影分支。可以明确点击“从这里继续”，或从来源消息再分出桌游方向。
3. 加入票据样例，再比较三个结构。它是显式载入虚构夹具，包含预先明确的关联；不是调用 Wayfinder，也不是依据聊天推断票据。
4. 在 A 中收起与展开讨论，查看是否仍理解当前继续的位置。
5. 打开 #12，模拟来源记录已解决，再重新打开。#13 解锁或恢复等待，但不自动完成或开始聊天。

## 已观察到的行为

通过本机 Chrome 实际点击与截图检查，未新增测试文件：

- 从电影分支回看来源后，查看位置为“聚会想法”，继续位置仍为“一起看一部电影”；明确继续才切换。
- 分支从所选消息截取已有路径，后续添加的样例消息只进入该分支；一张票仍关联多个分支，没有按分支复制票据。
- 关闭详情、收起讨论、拖动卡片和查看整体不修改票据状态或继续位置；拖动时连线跟随。
- #12 已解决时 #13 可推进；重新打开 #12 后 #13 恢复等待。
- 改名、新开独立会话、缩略图导航、tips 关闭重开、三种 URL 方案、输入框方向键可操作。
- 390px 页面无外壳横向溢出，聊天面板覆盖画布；减少动态效果时转场为 0 秒。
- 浏览器操作过程无 pageerror，`git diff --check` 通过。

## 结论与边界

**交互路径可操作，布局选择尚未经过用户体验确认。** 初步观察：A 聚合一张票的讨论，B 更直接展示全部关系，C 强调当前思路；不能据此宣称某方案已经胜出。

本轮没有连接 Pi SDK、真实 tree/fork、模型、Matt skills、tracker 或持久化。分叉复制路径只是浏览器模拟，不能作为 Pi 上下文隔离已完成的证据。样例票据字段仅用于排版，不是 Matt 格式规范。没有实现工作区切换、多画布、手动分组/关联、外部同步、多个阻塞前提、自动命名和实际结果交接。大量节点的容器边界、连线避让、缩略图范围与长内容仍需后续验证。
